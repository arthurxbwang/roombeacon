# 设备台账、安装模板与会议室业务方案

2026-09-23，已部署并完成真实 HTTPS 管理页验收，运行 SHA 为 `4b65ecc`，见[发布与回退记录](production-inventory-templates-2026-09-23.md)。需求 [#25](https://github.com/arthurxbwang/roombeacon/issues/25)，接续已部署的 [#23](https://github.com/arthurxbwang/roombeacon/issues/23) 型号模板；开发基线为 `3cb966e`，前序生产版本见[型号模板发布记录](production-model-templates-2026-09-23.md)。

## 关联方式与选择理由

采用「硬件方案 → 安装模板 → 设备 → 会议室」，会议室另有自己的业务方案：

| 对象 | 管理内容 | 关系 |
|---|---|---|
| 硬件方案 | 型号、GPIO 接线、有效电平及参考固件 | 一个方案可供多个模板使用 |
| 安装模板 | 选择硬件方案，设置方向、页面版本、昼夜、语言及灯控开关 | 同型号可建立横版、竖版、不同语言等模板，供多台设备复用 |
| 设备 | 唯一码、身份、实物信息、会议室绑定、已发布配置及回执 | 一台设备当前绑定一间会议室；一间会议室可以有多台设备 |
| 会议室 | 飞书目录、地区、位置、日程及业务规则 | 不直接依赖具体型号与安装方向 |
| 会议室业务方案 | 官方签到或 V5 确认使用、宽限期、受控释放等 | 随会议室保留，不因换设备或换模板而切换 |

例如「BX68 硬件方案」可以建立「BX68 横版中文」「BX68 竖版英文」两个模板，分别下发给北京同一会议室的两台门牌；两台设备共享日程及签到规则，各自保留方向与语言。

将会议室固定嵌套在硬件方案或模板里，会导致同款硬件按房间大量复制模板，也使换机影响房间业务。让会议室分别直接绑定硬件和模板，则容易出现房间硬件与模板硬件不一致，并限制一房多屏。设备是实际安装位置与硬件的交汇点，适合作为这两种关联的承载对象。

当前下发采用**配置快照**：设备保存下发时的具体参数，后续模板编辑不会自动传播。新增下发请求携带模板 ID 和版本，服务器在同一事务内校验版本并读取已保存参数；设备配置历史仍可回退。当前不维护会自动追随模板最新版本的设备外键，也不自动批量更新正在运行的门牌。

## 页面操作

- 设备台账新增地区／园区与多级位置筛选；会议室列表复用同一筛选。关键字覆盖短码、SN、MAC、型号、地区、会议室名称和完整位置，兼容分组短码及空格输入。
- 位置按缓存目录的完整 `location` 路径逐级展开，不限制楼栋／楼层两级。父级变更清除下级路径；无匹配结果明确提示。未绑定设备可独立筛选，不根据网络地址猜测地区。
- 设备配置窗口沿用台账位置筛选，提供会议室关键词与结果数量。改变地区或路径后清理不再匹配的房间选择，避免同名房间错绑。
- 台账更改地区、位置、状态或关键词时清理不可见的批量选择，避免误发其他地区设备。
- 台账不再提供独立方向或硬件参数编辑。选择「硬件安装模板」应用整套参数；未选模板时保留设备当前配置，旧设备无需强制迁移。只读账号仅查看。
- 配置模板提供明确的「新建模板」「编辑」「复制调整」入口，支持改名、型号方案、方向、页面、语言、昼夜、灯控设置。切换页签保留未保存草稿。保存后明确提示尚需下发，模板编辑不会立即改变设备。
- 硬件接线和高低电平仍随已验证方案选择：BX68 为低电平点亮、旧 RK3568_R 为高电平点亮。管理员可在模板中选择方案并保存、编辑；本次不开放任意 GPIO 或修改已发布方案含义。新增硬件接线需按[型号模板规范](device-model-templates.md)验证并扩展 APK。
- 在「会议室 → 业务方案」进入既有房间规则管理。V4/V5/V6 页面版本只控制展示；业务方案切换继续经过原有权限、白名单和实例保护，不因选择模板而开放预约写入。

## 接口、并发和兼容

保留所有旧 API、Redis 键及浏览器键。新增 `PUT /api/v6/admin/templates/{id}`，提交 `name`、`config` 和 `expected_revision`；管理员身份、CSRF 与同源检查沿用既有机制。GET 模板列表增加 `revision`，旧模板默认第 1 版；空白名称和非法型号参数返回 422，模板不存在返回 404，版本冲突返回 409，失败保留编辑内容。

版本信息保存在新增的 `template_versions` 表，原 `templates` 三列及设备配置格式保持不变。旧客户端仍可按原请求新增模板或直接下发具体配置。新版单台与批量下发增加可选 `template_id`、`template_revision`，服务端按已保存模板解析实际配置，并继续执行型号差异确认和设备版本校验；任意错误整笔事务回滚。刷新计数与会议室绑定按设备保留。

单台编辑持有选择时的模板快照与版本；后台轮询不会把尚未确认的新模板内容偷偷替换进下发请求。模板改动后重新发布必须重新选择该模板。异型号二次确认、旧 APK 不完整应用提示、历史回退及审计均沿用已上线 #23 行为。

## 验证与发布边界

本轮使用模拟目录及隔离 API，不连接飞书或生产 Redis；浏览器测试不代表真实会议室绑定验收。Ruff 0.16.7、后端 300 项全量测试通过，无跳过；前端依赖安装、类型检查和生产构建通过，106 项 Chromium 全量回归通过，最后的关键词选择清理完成 18 项管理页定向复测，业务方案独立保存另补 1 项通过。Android 沿用已发布源码，重新完成 17 项原生测试、Lint 和 APK 构建，未安装到设备。模板卡片与窄屏布局使用模拟数据截图核对。

环境修复记录：首次全量后端测试因独立 Redis 缺少动态库而启动失败，补齐该测试程序的 `LD_LIBRARY_PATH` 后重新执行 300 项全部通过；未修改测试来跳过失败。

用户随后授权先部署验收、再推送 GitHub，已按固定提交发布并完成真实管理页验证；见[发布记录](production-inventory-templates-2026-09-23.md)。本轮没有合并 main、更新 APK 或新增 APK 协议。回退到本次基线时保留数据库及新增版本表，旧代码忽略该表，不清空设备身份或配置历史。若旧版直接修改模板后再次升级，须核对版本表与模板内容，不复用旧浏览器中的未提交草稿。
