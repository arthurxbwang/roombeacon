# 旧10.1寸测试机首装型号修复（#73）

更新：2026-10-10。用户已授权实施、GitHub PR和生产上线；本地配置声明与回归已准备，真实配置切换随后登记。

## 原因

旧测试机 `10.0.51.170` 为 `rk3568_r`，固件 `rk3568-11.0-20230426.150223`，Android11，与正式APK0.7.0已有旧机支持一致。硬件、固件和支持代码未变化。10月8日准备后台首装默认包时，私有 `ROOM_DISPLAY_INSTALL_MODELS` 只登记了新13.3寸机 `RK3568`；旧机原有已装应用不依赖这项首装检查，卸载后重新走后台首装才暴露遗漏。

后台“该设备型号不适用于默认安装包”来自安装前型号声明的精确匹配，并不是APK启动后判定硬件失败。此前#70取消的是IP／网段名单，没有修改型号声明。

## 修复范围

公开配置模板 [installation-models.conf](../scripts/production/installation-models.conf) 声明 `ROOM_DISPLAY_INSTALL_MODELS=RK3568,rk3568_r`。该文件仅含型号，不包含服务器私有配置或凭证。生产从GitHub获取准确已合并提交，将这一键合并进原私有 `installation.env`；不能整文件替换私有配置，不改APK路径、摘要、签名、ADB工具／端口及其他环境值。

当前默认正式APK0.7.0及应用／H5 `35ca0d9fb5954308f008932fb94cd02bd3776882`保持。两款已验证设备均可通过首装型号检查，未知和近似型号仍拒绝，原正式签名／摘要、管理员／CSRF、型号／序列号、固定transport和安装后读回保持。旧机配置会议室时选择10.1寸硬件模板：高电平RGB、GPIO154红／148绿／147蓝；不能选择新机低电平接线。

## 验证和上线

新增回归从公开模板读取真实配置，通过现有默认APK校验、检测和初始化API，覆盖 `RK3568`、`rk3568_r` 可用及 `rk3568`、未知型号拒绝；ADB和APK外部边界mock隔离。594项全量后端、Ruff0.16.7和diff检查通过，无跳过；前端／原生源码不变，未重复执行浏览器或Android构建。首装仅对检测出的实物身份执行，不把IP作为永久身份。

生产目标为独立 `roombeacon.thundersoft.com`、`/data/roombeacon`。修正前保存私有环境文件、SQLite一致性备份、设备／模板／策略与预约基线，核实无在途首装／释放任务并临时暂停释放；测试准确GitHub提交后，核对默认APK摘要／签名与两款型号声明，仅修正环境键、重启后台。真实HTTPS重新检测 `.170` 的目标结果为200且 `can_initialize=true`；实际安装由用户在后台确认，不自动安装／启动新设备或下发配置。

恢复前核对完整采集、新鲜来源配对、原预约／身份／配置保持、既有门牌页面／灯控和真实业务心跳健康，再恢复发布前释放状态。无前端／Android源码变化，本轮不重新构建APK；真实首装及旧机灯控交付仍由现场验收。

## 回退

应用／H5保持准确 `35ca0d9`，本轮无需应用切换。配置回退恢复本次备份的 `installation.env` 并重启后台，保留SQLite和Redis；旧值 `RK3568` 会再次阻止旧机首装，需明确告知。已完成的真实安装不会随配置回退卸载或清数据。恢复释放前仍须核对采集、设备与在途任务。
