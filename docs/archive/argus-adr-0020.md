## 背景

会议室门口的 iPad 需要展示飞书预约数据。项目负责人明确要求先复用蓝绿机资源和 Argus 接口能力，由 WAF 引出独立页面和专用端口，后续再评估拆分。飞书凭证管理、HTTP 连接器、Redis、事件监听和管理端认证与 Argus 现有能力重叠。

## 决策

2026-09-16 修订：独立门牌改为服务启动后集中采集，与终端请求解耦。展示 API 只读 Redis，后台默认 5 分钟全量分批更新，固定窗口锁防止多进程重复采集；最近成功快照保留 7 天，过期继续显示历史内容但不宣称实时空闲。下述按需刷新描述仅保留为原始集成方案记录。

2026-09-15 修订：用户关闭原 PR #165，改为独立测试机部署 HTTP 80。复用 Feishu 连接器与授权、H5 和缓存逻辑；独立 ASGI 入口只注册展示 API，本机 Redis、SSH 管理凭证，不启动 Argus 数据库、Celery 或 WS。以下蓝绿描述为被替代的原决策。实施以独立门牌手册为准。

- 在现有仓库内新增会议室领域模块，不创建独立业务服务或数据库。
- Vite 多入口构建 `room-display.html`，独立入口不加载平台导航和管理路由；Argus `/meeting-rooms` 提供管理员预览、凭证签发及撤销。
- Blue、Green 的 Nginx 各提供专用端口，通过 WAF 独立域名访问。后端仍使用本机已有 FastAPI 进程。端口模板只开放门牌 HTML、静态资源、准确路径的展示 GET API。
- 门牌使用独立随机凭证，绑定单个会议室，30 天过期，Redis 只保存 SHA-256 摘要。`get_current_user` 在准确的展示 GET 路径识别此受限身份，其他路径、方法一律拒绝；该凭证不是用户 JWT，不能刷新为用户身份。
- 采用按需刷新、最多 20 间一批的 Redis 共享快照，5 分钟有效；事件通知标记失效，30 秒组级刷新冷却抑制并发与失败重试风暴。没有在线门牌或预览请求时不轮询飞书。
- 主题查询为可降级富化；组织者不可见时不展示主题。预约占用不解释为实际有人，错误或过期数据不解释为空闲。
- WAF 门牌入口须随批准方案与主入口协调切换；当前蓝绿脚本不会自动更新新增的 WAF 入口。

## 后果

### 正面

复用既有应用权限、资源和发布流程；无需新增机器、数据库迁移或依赖。设备端不保留管理员登录，未来可沿领域模块边界拆分。

### 负面

门牌与 Argus 后端共享故障域与发布周期。Redis 不可用时展示接口拒绝访问，凭证被淘汰或到期需要重新绑定。当前同一会议室只有一份有效凭证，替换会影响使用该凭证的所有设备。独立 WAF 入口需要运维纳入逐节点切流与回退清单。

## 备选方案

### 方案 A: 独立机器和服务

隔离部署周期，但初期需要重复建设鉴权、配置与监控；待设备规模或可用性要求明确后再评估。

### 方案 B: iPad 登录 Argus 管理账号

实现简单，但走廊设备会持有平台级权限，不采用。
