2026-09-23 已部署并完成 BX68 样机验收，需求 [#23](https://github.com/arthurxbwang/roombeacon/issues/23)，准确 SHA、回执与回退见[发布记录](production-model-templates-2026-09-23.md)。

本次发布经用户明确批准仓库规则例外，按指定顺序，将本地固定 Git 提交通过 bundle 导入生产仓库，再由服务器按该 SHA 检出并构建；验收后推送同一提交到 GitHub，不复制未提交源码。用户另行临时开启 BX68 网络 ADB，用于备份及原位升级 APK。

> 后续本地开发已增加模板原位编辑、方向归模板、台账分层筛选和独立业务方案入口，尚未发布，见[设计与交付](device-inventory-templates.md)。下文保留本次已发布行为。

## 模板内容与操作

配置模板和单台设备使用同一套表单：

- 设备型号：BX68 13.3 寸 1080P、旧 RK3568_R 1280×800，或通用屏幕（无灯控）。模板型号固定 GPIO 通道、有效电平，并展示参考固件，在表单中直接显示。
- 显示方案：V6 自动适配房间方案、V4 官方签到、V5 确认使用；不改变房间本身的签到／释放规则。
- 横屏／竖屏。
- 自动切换白天／黑夜：打开后使用房间城市的日出日落；关闭后始终白天。受管门牌没有可用城市时间时以白天兜底，不提供固定黑夜配置。旧版主控的日夜测试按钮保留。
- 门牌语言：简体中文／English，覆盖门牌状态、时间日期、官方签到卡和 V5 签到状态。会议室名称、会议主题和人员姓名保留上游原文；后台与 Android 待部署页继续使用中文。
- 同步侧边灯开关；通用屏幕固定关闭。

「复制调整」将已保存模板载入为新草稿，再保存成新模板，原模板和已下发设备保持原配置。在台账选择模板批量发布时，使用所选模板的已保存配置，不会误发另一个正在编辑的草稿。会议室绑定与刷新计数按设备保留。

## 型号与接线

| 模板型号标识 | 系统型号 | 红／绿／蓝 GPIO | 点亮／熄灭电平 |
|---|---|---|---|
| `bx68` | `RK3568` | 148／154／147 | 0／1 |
| `rk3568_r` | `rk3568_r` | 154／148／147 | 1／0 |
| `generic` | 任意屏幕 | 不操作 GPIO | 不适用 |

完整固件标识和现场校准证据见[型号接线记录](android-device-profiles.md)。模板下发只比较设备上报的 `Build.MODEL`：相同型号普通提示，不同或未上报型号二次确认后允许强制下发；固件差异不作为拦截条件。接线由服务端型号目录提供给前端，Android 按后台选定的模板执行，不再用本机型号／固件否决。旧配置 `auto` 继续保留精确型号加固件的自动识别行为。

已发布型号标识对应的接线必须保持不变。新设备或新接线先做现场验证，再以新的型号标识扩展服务端目录及 Android 白名单和测试；不能修改既有标识的含义，让已保存模板悄悄改线。IO4／继电器不在控制范围。

## 下发、兼容与失败行为

`DeviceConfig` 新增 `device_profile`、`theme_mode`、`language`；旧记录缺字段时采用 `auto`（原生精确匹配）、自动昼夜、中文，不重写历史数据库。旧模板显示「未指定型号」，复制后需选择明确型号；通用屏幕不启用灯控。旧客户端的模板 API 请求仍兼容，保留 `auto` 默认，新增前端创建的模板均绑定明确型号。

`GET /api/v6/admin/device-profiles` 只允许管理员或只读管理账号读取。原有模板保存、单台下发、批量下发的写权限／CSRF／版本检查继续有效。固定黑夜、未知语言、未知型号、通用屏幕启用灯控及额外 GPIO 字段被拒绝。

单台发布、模板批量发布和历史回退采用相同的后台交互：

1. 同型号只显示「型号相同，可正常下发」，普通发布不额外弹窗。
2. 型号不同或缺失时显示差异提示；点击下发后，列明模板型号、差异设备及数量，确认后强制下发，取消不提交。
3. 服务器使用当前台账再次比对型号，异型号请求需带本次操作的 `confirm_model_mismatch: true`。该标记不进入模板、设备配置或历史配置，不会使下一次修改自动强制。
4. 操作日志记录实际设备型号、模板型号标识和 `model_override`，后台列表标注强制下发。已下发配置的远程刷新不重复要求型号确认。
5. 确认不跳过管理员权限、CSRF、设备配置版本、会议室有效性或批量事务检查；任意版本冲突仍整批回滚。停用／撤销无需型号确认。

APK 0.6.2（versionCode 9）上报 `firmware` 和 `config_schema=2`，并执行后台选择的灯控方案，包括跨型号确认后的方案。旧 APK 仍允许保存和下发；但它不理解模板灯控，后台显示升级提示，旧 APK 心跳也不会被显示成完整应用成功。升级后下次同步自动清除该兼容提示。显示、方向、昼夜和语言的其他兼容能力保持。

Android 不再拦截型号差异。如果当前设备无法打开模板对应的灯控接口，报告灯控不可用并继续展示页面。未知、失联、后台、状态过期仍按当前选用方案尝试熄灯；硬件损坏／进程强杀不能保证熄灯。GPIO 仍来自模板定义，不接受任意 sysfs 路径。

已认证展示接口在响应中附带当前设备的 `display_preferences`，不写入共享房间缓存，避免同房间的设备互相覆盖语言或昼夜选择。新版 APK 同时携带经过白名单验证的展示参数，使缓存故障下的冷启动也保留配置。认证失效仍显示未知，不显示空闲或签到成功。

发布时先部署兼容新字段的后端与前端，再升级 APK 0.6.2 以执行模板灯控；也可先在后台确认下发并等待设备升级。旧后端严格拒绝未知元数据字段，不能先升级 APK。本次先通过 Git bundle 部署固定提交 `808710d`，再升级 BX68 APK 并验收；验收后推送 GitHub。其他型号实机及跨昼夜长稳另行记录。

若需回退后端，先回退 APK，并把本次新增的设备配置调整回旧版字段且保留历史备份，再回退对应服务；不要把带新增字段的模板直接交给严格旧版写入接口。数据库身份、会议室绑定、账号与配置历史不能清空。只回退前端页面或 APK 时，也需核对显示设置是否仍受支持。
