### 1.2 接口与接线定义

传感器背面提供 4 位压线端子柱（适用线径 0.75 ~ 1.5 平方毫米，最大拧紧力矩 0.1 N·m）：

```
+---------------+
|   接线柱说明   |
+---+-----------+
| + | DC 9~28V  | ---> 电源正极 (典型 12V/24V)
| - | GND       | ---> 电源负极 / 接地
| A | RS485 A   | ---> RS485 数据差分正端 (D+)
| B | RS485 B   | ---> RS485 数据差分负端 (D-)
+---+-----------+
```

> **注意**:
> 1. 传感器内部 **未焊接 120Ω 终端电阻**。若传感器处于 RS485 总线拓扑的最末端且布线距离长，请在外部 A、B 之间并接 120Ω 终端匹配电阻。
> 2. 正负极切勿反接，建议使用屏蔽双绞线 (STP) 传输 RS485 信号。

## 2. RS485 与 Modbus 通信基础

### 2.1 物理层串口通信参数

| 串口参数项 | 默认配置 | 可选范围 | 变更生效机制 |
| :--- | :--- | :--- | :--- |
| **波特率 (Baudrate)** | `9600 bps` | `1200, 2400, 4800, 9600, 19200, 38400, 57600 bps` | 修改后设备响应完成**立即生效** |
| **数据位 (Data Bits)** | `8 bit` | 固定 8 | 不可修改 |
| **校验位 (Parity)** | `None (无校验)` | 固定无 | 不可修改 |
| **停止位 (Stop Bits)** | `1 bit` | 固定 1 | 不可修改 |
| **从机地址 (Slave ID)** | `0x01` (十进制 1) | `1 ~ 247` (0 为广播地址) | 写入后立即生效 |

### 2.2 Modbus 协议规约与端序规范

1. **协议规范**: 标准 Modbus RTU 协议。
2. **端序标准**:
   - **寄存器地址与数据域**: **大端序 (Big-Endian)**，即高字节 (Hi) 在前，低字节 (Lo) 在后。
   - **CRC 校验码**: **小端序 (Little-Endian)**，即 CRC 低字节在前，CRC 高字节在后 (采用 Modbus CRC-16，多项式 `0xA001`)。
3. **支持的功能码 (Function Codes)**:
   - `0x04`: 读输入寄存器 (Read Input Registers，对应 PLC 组态 `3xxxx` 地址段)。
   - `0x03`: 读保持寄存器 (Read Holding Registers，对应 PLC 组态 `4xxxx` 地址段)。
   - `0x06`: 写单个保持寄存器 (Write Single Register)。
   - `0x10`: 写多个保持寄存器 (Write Multiple Registers)。
4. **异常响应 (Exception Response)**:
   - 当请求非法或发生错误时，从机响应功能码为 `请求功能码 + 0x80`，并附带 1 字节异常码。

## 3. 核心运行机制与数据结构定义

### 3.1 距离门划分与分辨率模式 (80cm vs 20cm)

雷达探测空间沿法线方向分割为多个连续的「距离门」(Distance Gates)：
- **80cm 模式 (默认模式, 寄存器 0x0009 = 0)**:
  - 每个门步长为 `0.8 m` (80cm)。
  - 门有效数量为 **11 个门** (门 0 至 门 10，覆盖 0 ~ 8.8m)。
  - 门 11 以后数据无效，读取时填充 `0`。
- **20cm 模式 (高精模式, 寄存器 0x0009 = 1)**:
  - 每个门步长为 `0.2 m` (20cm)。
  - 门有效数量为 **25 个门** (门 0 至 门 24，覆盖 0 ~ 5.0m)。

### 3.2 门能量与门阈值数据打包机制 (高低字节对)

为了节省寄存器开销，实时能量数据和门阈值均采用 **16 位寄存器容纳 2 个门** 的复合格式：
- **高字节 (Bits 15~8)**: 偶数距离门 (Gate $2n$)，数值范围 `0 ~ 99`。
- **低字节 (Bits 7~0)**: 奇数距离门 (Gate $2n+1$)，数值范围 `0 ~ 99`。
- **示例**: 寄存器读取值为 `0x323C` 时，表示门 $2n$ 的能量/阈值为 `50 (0x32)`，门 $2n+1$ 的能量/阈值为 `60 (0x3C)`。

### 3.3 距离门使能位掩码 (Bitmask)

距离门的开关状态使用 16 位/32 位掩码表示：
- `1` = 该距离门探测开启；`0` = 该距离门探测屏蔽（用于过滤空调、吊扇等固定晃动物体）。
- **80cm 模式**: 使用低 16 位寄存器即可（例如 `0x07FF` 二进制为 `0000 0111 1111 1111`，bit0~bit10 全为 1，即门 0~10 全开）。
- **20cm 模式**: 共 25 个门，由两个寄存器组成（H 寄存器容纳 bit16~24，L 寄存器容纳 bit0~15）。全开时 $H = \text{0x01FF}$, $L = \text{0xFFFF}$。

### 3.4 触发距离过滤机制 (防边缘误触发)

- **应用场景**: 传感器装于房门或隔断附近（如距门 1m），而需要探测房间内 3m 空间。如果门外经常有人走动，可能引起误触发。
- **运行逻辑**:
  - 当 `触发距离使能 (0x000D) = 1` 时生效，必须联动设置「最近触发距离」和「最远触发距离」。
  - **初始无人时**: 仅当人体进入 `[最近触发距离, 最远触发距离]` 范围内时，传感器才从「无人」切入「有人」。
  - **切入有人后**: 检测范围自动恢复扩展到全局设定的 `[最近检测距离, 最远检测距离]`，维持检测状态，防止人微动时掉线。

### 3.5 光照联动控制逻辑

- **光照阈值 (0x000B)** 默认设为 `0`，此时光感联动关闭，人员状态直接根据雷达微波信号输出实际有/无人。
- 当 **光照阈值 > 0** 时：
  - 若 `当前环境光照度 < 设定光照阈值` **且** 雷达检测到有人 $\rightarrow$ 输出 **有人 (1)**。
  - 若 `当前环境光照度 ≥ 设定光照阈值` $\rightarrow$ 强制输出 **无人 (0)** (即使有人也不触发，适用于白天无需开灯的节能场景)。

### 3.6 数据主动上报模式 (Heartbeat & Event Push)

- 保持寄存器 `0x000A` 设为 `1` 开启主动上报：
  - **状态变化上报 (Event-Driven)**: 当人员状态在「有人/无人」之间切换时，设备主动向 485 总线推送一帧报文。
  - **周期性心跳上报 (Periodic Heartbeat)**: 按照寄存器 `0x000C` 设定的时间间隔 (默认 600s)，即使状态无变化也周期性推送心跳。
  - **上报报文内容**: 格式与主机执行 `01 04 00 00 00 01` (读取人员状态) 的从机应答报文完全相同 (`01 04 02 00 [状态] [CRC_L] [CRC_H]`)。

## 6. Modbus 报文帧详解与测试用例集

所有示例报文均经过 **Modbus CRC-16 校验验证**（从机地址以 `0x01` 为例）。

### 6.1 读输入状态寄存器示例 (0x04)

#### 6.1.1 读人员状态 (0x0000)

## 8. 常见现场干扰排查与工程建议

### 8.1 典型干扰源与对策

1. **绿植摆动与气流吹拂**:
   - 空调出风口吹动阔叶绿植、日历纸张是主要误报源。
   - *对策*: 调整出风口百叶，或通过寄存器 `0x000D~0x000F` 限制触发距离，避开绿植摆动半径。
2. **金属扇叶与强振动排气扇**:
   - 排风扇金属叶片高速旋转或引起石膏板吊顶共振。
   - *对策*: 传感器不可正对排气扇；加固吊顶轻钢龙骨，确保传感器底座刚性固定无晃动。
3. **玻璃/轻质木板隔断穿透**:
   - 24GHz 毫米波雷达对普通单层玻璃、石膏板、空心木门有穿透性。
   - *对策*: **不要** 将最远探测距离设为最大（8.4m）。现场实测传感器到隔断的直线距离（例如 3.2m），将 `0x0000` 最远检测距离设为 `3.0m`，即可阻断隔断外的走动干扰。
4. **长摆幅窗帘/带下轨金属卷帘**:
   - 强风吹动厚重窗帘或金属卷帘易触发雷达。
   - *对策*: 适当关闭对应距离门（通过写寄存器 `0x0011` / `0x0013` 掩码关闭窗边距离门）。

### 8.2 通信异常排查清单

- **收不到应答**:
  - 检查 A/B 线是否反接（485 A 对应 D+，B 对应 D-）。
  - 确认波特率（默认 9600）和从机地址（默认 1）是否匹配。
  - 使用万用表测量 A-B 直流压差（空闲时 A 对 B 应为 `+0.2V ~ +0.5V`）。
- **出现 CRC 校验错误或乱码**:
  - 检查接线是否可靠接触，是否在长距离总线末端安装 120Ω 终端电阻。
  - 排查是否有强电线（220V AC）与 RS485 信号线同管平行动线。

## 9. Agent 快速集成代码实现 (Python 驱动范例)

以下为轻量级、无第三方重型依赖的 Python 3 驱动实现，包含 CRC16 计算、报文组包、响应解析及高低字节解包：

```python
"""
dp72_drt_driver.py
DP72_DRT 24GHz FMCW 毫米波人体存在传感器 Modbus-RTU 驱动程序
"""

from typing import Dict, Any, Tuple, List, Optional
import struct

def modbus_crc16(data: bytes) -> bytes:
    """计算 Modbus-RTU CRC-16 校验码 (返回 2 字节小端序: Low byte, High byte)"""
    crc = 0xFFFF
    for byte in data:
        crc ^= byte
        for _ in range(8):
            if crc & 1:
                crc = (crc >> 1) ^ 0xA001
            else:
                crc >>= 1
    return struct.pack('<H', crc)

def build_read_command(slave_id: int, func_code: int, start_reg: int, reg_count: int) -> bytes:
    """构造读寄存器报文 (0x03 或 0x04)"""
    payload = struct.pack('>BBHH', slave_id, func_code, start_reg, reg_count)
    return payload + modbus_crc16(payload)

def build_write_single_command(slave_id: int, reg_addr: int, value: int) -> bytes:
    """构造写单个寄存器报文 (0x06)"""
    payload = struct.pack('>BBHH', slave_id, 0x06, reg_addr, value)
    return payload + modbus_crc16(payload)

def build_write_multiple_command(slave_id: int, start_reg: int, values: List[int]) -> bytes:
    """构造写多个寄存器报文 (0x10)"""
    reg_count = len(values)
    byte_count = reg_count * 2
    header = struct.pack('>BBHHB', slave_id, 0x10, start_reg, reg_count, byte_count)
    data = b''.join(struct.pack('>H', val) for val in values)
    payload = header + data
    return payload + modbus_crc16(payload)

def verify_and_unpack_response(raw_resp: bytes, expected_slave_id: int, expected_func: int) -> bytes:
    """校验响应帧合法性与 CRC，返回纯数据载荷 (Payload Data)"""
    if len(raw_resp) < 5:
        raise ValueError(f"响应长度过短: {len(raw_resp)} 字节")

    # 校验 CRC
    data_part, recv_crc = raw_resp[:-2], raw_resp[-2:]
    if modbus_crc16(data_part) != recv_crc:
        raise ValueError(f"CRC 校验失败! 接收到: {recv_crc.hex()}, 计算应为: {modbus_crc16(data_part).hex()}")

    slave_id, func_code = data_part[0], data_part[1]
    if slave_id != expected_slave_id:
        raise ValueError(f"从机地址不匹配! 期望 {expected_slave_id}, 收到 {slave_id}")

    if func_code == (expected_func | 0x80):
        error_code = data_part[2] if len(data_part) > 2 else 0
        raise RuntimeError(f"从机返回 Modbus 异常响应! 功能码 0x{func_code:02X}, 错误码: 0x{error_code:02X}")

    if func_code != expected_func:
        raise ValueError(f"功能码不匹配! 期望 0x{expected_func:02X}, 收到 0x{func_code:02X}")

    if expected_func in (0x03, 0x04):
        byte_len = data_part[2]
        return data_part[3:3 + byte_len]
    elif expected_func in (0x06, 0x10):
        return data_part[2:]
    return data_part[2:]

class DP72DRTSensor:
    """DP72_DRT 传感器高层抽象封装"""
    def __init__(self, slave_id: int = 1):
        self.slave_id = slave_id

    def cmd_query_status(self) -> bytes:
        """生成查询人员存在状态报文 (0x04, Reg 0x0000, 1 Reg)"""
        return build_read_command(self.slave_id, 0x04, 0x0000, 1)

    def cmd_query_telemetry(self) -> bytes:
        """一次性读取核心遥测: 状态、光照、距离、健康状态 (0x04, Reg 0x0000~0x0003, 4 Regs)"""
        return build_read_command(self.slave_id, 0x04, 0x0000, 4)

    def cmd_set_departure_delay(self, seconds: int) -> bytes:
        """设置无人消失延时时间 (0x06, Reg 0x0003, 单位秒)"""
        if not (0 <= seconds <= 3600):
            raise ValueError("延时时间需在 0~3600 秒之间")
        return build_write_single_command(self.slave_id, 0x0003, seconds)

    def cmd_set_sensitivity(self, motion_sens: int, presence_sens: int) -> bytes:
        """同时写入运动与存在灵敏度 (0x10, Reg 0x0004~0x0005)"""
        for s in (motion_sens, presence_sens):
            if not (0 <= s <= 9):
                raise ValueError("灵敏度取值范围为 0~9")
        return build_write_multiple_command(self.slave_id, 0x0004, [motion_sens, presence_sens])

    def cmd_set_detection_range(self, min_meters: float, max_meters: float) -> bytes:
        """同时设置最近与最远探测距离 (0x10, Reg 0x0000~0x0001, 单位米)"""
        min_reg = int(round(min_meters * 100))
        max_reg = int(round(max_meters * 100))
        if not (0 <= min_reg <= max_reg <= 840):
            raise ValueError("距离必须满足 0 <= 最近 <= 最远 <= 8.4m")
        return build_write_multiple_command(self.slave_id, 0x0000, [max_reg, min_reg])

    @staticmethod
    def parse_telemetry_payload(data: bytes) -> Dict[str, Any]:
        """解析 0x04 寄存器 0x0000~0x0003 的 8 字节数据"""
        if len(data) < 8:
            raise ValueError("遥测数据长度不足 8 字节")
        status, lux_raw, dist_raw, health = struct.unpack('>HHHH', data[:8])
        return {
            "occupied": (status == 1),
            "status_code": status,
            "illuminance_lux": round(lux_raw * 0.1, 1),
            "target_distance_m": round(dist_raw * 0.01, 2),
            "device_healthy": (health == 1),
            "health_code": health
        }

    @staticmethod
    def parse_gate_energy_payload(data: bytes) -> List[int]:
        """解析距离门实时能量数据（每个字节对应 1 个门的能量值 0~99）"""
        return list(data)
```

## 10. 附录：十六进制速查精简卡 (Cheat Sheet for Agents)

| 意图 | 发送报文 (Hex) | 响应格式 (Hex) | 字段解析核心 |
| :--- | :--- | :--- | :--- |
| **查询有无人** | `01 04 00 00 00 01 31 CA` | `01 04 02 00 [ST] [CRC]` | `ST=01` 有人，`ST=00` 无人 |
| **查询光照度** | `01 04 00 01 00 01 60 0A` | `01 04 02 [HI] [LO] [CRC]` | 光照 = `(HI*256+LO) * 0.1 Lux` |
| **查询距离** | `01 04 00 02 00 01 90 0A` | `01 04 02 [HI] [LO] [CRC]` | 距离 = `(HI*256+LO) * 0.01 m` |
| **查询设备健康**| `01 04 00 03 00 01 C1 CA` | `01 04 02 00 [ST] [CRC]` | `ST=01` 正常，`ST=02` 异常 |
| **设延时15秒** | `01 06 00 03 00 0F 39 C8` | 原样回传 | 寄存器 `0x0003` 写入 `15` |
| **设灵敏度为7** | `01 06 00 05 00 07 18 09` | 原样回传 | 寄存器 `0x0005` (存在灵敏度) 设为 `7` |
| **设最远探测5m**| `01 06 00 00 01 F4 89 D2` | 原样回传 | 寄存器 `0x0000` 写入 `500` (5.0m) |
| **开主动上报** | `01 06 00 0A 00 01 68 08` | 原样回传 | 寄存器 `0x000A` 设为 `1` |
