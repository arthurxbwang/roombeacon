# 默认首装APK与页面回执配套（#76）

2026-10-10。用户报告6QVB94“未上报页面状态，请升级APK”并要求重新部署APK；本次准备同签名覆盖升级该旧10.1寸测试机，并将后续默认首装包同步为既有正式0.7.1。

## 原因和范围

新设备已在线、配置3/3，实际包为0.7.0（10），心跳没有 `metadata.runtime`。持续页面／灯控回执从0.7.1（11）加入，旧首装默认包没有随着后台同步，导致新装设备立即显示升级提示。配置回执不能证明页面／灯控健康，后台仍应显示未确认，不能把提示改成正常掩盖缺少证据。

公开 [installation-apk.json](../scripts/production/installation-apk.json)锁定现有已批准0.7.1的包名、版本、摘要、证书和两款型号；[installation-models.conf](../scripts/production/installation-models.conf)继续保留两款型号。生产从准确GitHub提交读取清单，实际SDK工具验证二者相符，再仅将私有 `ROOM_DISPLAY_INSTALL_APK` 改为0.7.1文件路径。旧包、项目签名、两款型号、ADB端口及其他私有设置保持，不整文件覆盖环境。

当前既有批准包：`/data/roombeacon/shared/installation-packages/roombeacon-0.7.1-326790124fb2.apk`。沿用[10月9日批准的包和签名](production-native-health-upgrade-2026-10-09.md)，Android源码和二进制均不重新生成，应用／H5继续准确 `35ca0d9`。

验收须保持6QVB94、原设备ID／凭证摘要、3/3配置、应用UID和首次安装时间，实际新增runtime上报页面ready、H5／WebView，灯控状态与部署配置相符。管理在线不代替这项验收。
