# Android 样机型号与灯控映射

历史 APK 及旧配置 `auto` 按完整 `Build.MODEL` 和 `Build.DISPLAY` 自动识别接线，未匹配时不自动启用灯控。新增集中模板（本地未部署）由后台比较型号，相同型号普通提示，不同型号二次确认后允许强制下发；APK 0.6.2 直接执行所选模板接线。两套接线的现场校准记录如下。

## BX68 · 13.3 寸 1080P 新机

- 样机地址：`10.0.68.146`；当前绑定北京-203。地址仅为联调记录，不参与型号匹配。
- `Build.MODEL`：`RK3568`
- `Build.DISPLAY`：`RK3568_BX68_Android 11_64-20260331.094925_ZX-keys`
- Android 11 / API 30，ARM64，约 4GB 内存；物理 1920×1080，density 240，默认 WebView 1280×720 / DPR 1.5。
- 型号配置：`RoomLight.Profile.BX68`，自 Android 0.2.3 起采用正确极性和顺序。
- **2026-09-20 用户现场确认：IO1=绿，IO2=红，IO3=蓝；低电平点亮，111 全灭。** 单色测试的其他两路保持 1。

| 功能 | IO1 / GPIO154（绿） | IO2 / GPIO148（红） | IO3 / GPIO147（蓝） |
| --- | --- | --- | --- |
| 熄灯 / 未知 / 失联 / 后台 | 1 | 1 | 1 |
| 红 / 使用中 | 1 | 0 | 1 |
| 绿 / 空闲 | 0 | 1 | 1 |
| 蓝（记录接线，业务状态不使用） | 1 | 1 | 0 |
| 黄 / 即将开始（红绿混合） | 0 | 0 | 1 |

红、绿、蓝、全灭映射来自用户现场校准；黄色为红绿混合输出，混色实际色相仍以现场观察为准。IO4 / GPIO116 保持原值 0，不参与灯控。

切色先写 111 全灭，再拉低目标通道；未知状态、读取超时、后台和写入异常恢复均使用本型号的 111。写入失败只能尝试熄灯，不能保证硬件故障或进程强杀时熄灯。

**0.2.2 曾错误沿用旧机的高电平 RGB 规则。其读回通过只证明指令到达，不证明灯色或熄灯正确；不得再把 0.2.2 用于这台设备的灯光验收。** 回退到旧 APK 前须先关闭同步，并按本表将三路设为 111。

## 旧 RK3568 样机 · 1280×800

- 样机地址：`10.0.69.167`；当前北京-201。
- `Build.MODEL`：`rk3568_r`
- `Build.DISPLAY`：`rk3568-11.0-20230426.150223`
- 型号配置：`RoomLight.Profile.RK3568_R`，维持高电平 RGB：GPIO154=红、148=绿、147=蓝。
- IO1/IO2/IO3：红100、绿010、黄110、灭000；第四路 GPIO137 不操作。
- 现场证据和既有验证范围见 [旧机灯控记录](android-led-investigation.md)，不能把新机校准结论回写为旧机接线。

## 集中配置模板（本地未部署）

APK 0.6.2 上报完整固件和配置能力；后台模板按本页已验证的两套接线显示 GPIO 及有效电平。型号匹配与差异确认由后台完成；APK 执行后台指定的接线，不再硬性拦截异型号。完整流程与前后端／APK 升级顺序见[型号模板说明](device-model-templates.md)。

## 分辨率说明

默认配置下，1920×1080 物理像素对应 1280×720 CSS 像素，DPR 为 1.5。当前网页是 HTML 文字、CSS 与 SVG，不是先绘制整张 720P 位图再放大到 1080P。将 density 从 240 改到 160 会改变布局尺度和文字物理大小，不会增加面板像素；本次未调整 density 或分辨率。光栅动画的清晰度仍受源素材尺寸限制。

参考：[Android 屏幕密度](https://developer.android.com/training/multiscreen/screendensities)、[CSS 与物理像素比例](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)。
