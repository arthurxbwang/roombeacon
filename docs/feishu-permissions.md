# 飞书应用权限与独立迁移清单

更新：2026-09-17。当前短期借用 Argus 自建应用，后续切换 RoomBeacon 独立自建应用。只复用服务器上的应用凭证，不连接 Argus 生产 Redis，也不把本仓库代码回写 Argus。

## 姓名补全所需配置

后台以 `tenant_access_token` 调用 `GET /open-apis/contact/v3/users/{open_id}?user_id_type=open_id`，仅提取 `data.user.name`。不请求用户登录授权。

- 申请/核对应用身份的 `contact:user.base:readonly`（获取用户基本信息），用于姓名读取。
- 在开放平台核对“获取单个用户信息”接口的应用身份授权要求；已有 `contact:contact:readonly_as_app`（以应用身份读取通讯录）属于需要核对的既有通讯录授权，不应为了补姓名直接复制 Argus 的全部权限。最终权限组合以当前控制台该接口关联权限及真实调用结果为准。
- 通讯录数据授权范围应覆盖需要展示的会议组织者。开通 API 权限与授予人员数据范围是两件事；按组织实际需要选择人员/部门，不默认扩到全员。
- 按开放平台流程完成管理员批准及版本发布，确认权限实际生效。
- 本功能不需要手机号、邮箱、用户受雇信息、通讯录写入或消息发送权限，也不调用手机号/邮箱转 ID 接口。

官方核对入口：[获取单个用户信息](https://open.feishu.cn/document/server-docs/contact-v3/user/get)、[获取通讯录授权范围](https://open.feishu.cn/document/server-docs/contact-v3/scope/list)。控制台权限状态未在本次检查中核实，上述为配置核对清单，不是已授权证明。

## 已有会议室权限

原应用历史已申请 `vc:room:readonly`、`calendar:room:readonly`、`calendar:room`。当前调用会议室目录、层级、忙闲、日程主题接口。独立应用应按这些接口的官方关联权限重新核对，不把历史三项直接认定为最小权限集，也不复制 Argus 无关业务的权限。

## 实现与失败边界

- 仅在忙闲数据没有姓名、但有格式有效的 `open_id` 时补全；已有姓名优先，无 ID 不猜测。
- 每批最多查询 20 个不同 ID，并发请求各限时 3 秒；超出本批额度的人员在后续采集中重试。重复 ID 合并查询。
- `rooms:organizer:v1:{App ID 的 SHA-256 前 24 位}:{open_id}` 缓存成功姓名 300 秒、失败/空姓名 60 秒。成功缓存意味着权限撤销或改名最长可能延迟约 5 分钟再检查；已经生成的日程快照仍遵循原有有效期和离线展示规则。
- 权限拒绝、无效 ID、网络失败、超时或畸形数据均不伪造姓名，不改变忙闲时间，不使用过期姓名缓存兜底。失败日志只含错误类型；传输层只记录错误码，不记录响应体、姓名或凭证。
- 姓名补全不会扩大日程主题查询范围；忙闲接口原来未提供姓名的会议仍不因通讯录补全而额外获取主题。
- 不向终端新增 open_id 字段；终端仍只读缓存。

## 本次线上只读核查

2026-09-17，用门牌服务器现有应用查询北京 201 当日 09:30–10:15 的组织者：忙闲接口有 open_id、无姓名，通讯录接口返回 `41012`，无姓名结果。本次未保存或输出真实 ID、姓名、凭证或上游响应体。

这证明该场会议尚不能通过此接口补全；不能据此断言只缺权限。后续需核对 ID 对当前应用是否有效、人员类型与所属租户，以及通讯录范围；必要时由飞书支持协查。本地 mock 测试通过不等于该场线上修复成功。本次未部署代码、重启服务或调整飞书权限。

## 独立应用切换

1. 在目标企业创建独立自建应用，按本清单核对接口权限、通讯录范围及发布状态。
2. 在服务器安全配置中替换 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，不把凭证写入仓库或聊天。
3. open_id 按应用隔离；用新应用重新采集，不复制旧应用的 ID 到新应用查询。姓名缓存自动使用新的 App ID 命名空间，旧缓存自然过期。
4. 切换应明确 Git SHA、目标服务及回退配置，保持只有一个采集进程。API、设备凭证、主控凭证与 Redis 原有键保持兼容，不执行 flushall。
5. 已有快照可能包含旧应用取得的姓名；切换验收需等待一次完整的新应用采集，检查数据时间、姓名补全及权限拒绝场景，不能只看旧缓存。
6. 回退时恢复原应用配置及原代码 SHA；不影响 Argus 自身的应用配置。待门牌独立验证完成后再评估旧应用权限，不能直接撤销 Argus 仍在使用的权限。
