# V7 品牌签到门牌

更新：2026-09-28。需求：[Issue #31](https://github.com/arthurxbwang/roombeacon/issues/31)。用户确认的方案 A 精简版已通过 PR #32 合入并部署生产，W9TW7S 已应用；准确提交、实机证据与回退见[上线记录](production-v7-2026-09-28.md)。

## 页面与交互

- 三栏布局保留房间、会议与后续日程，左侧显示本场开始／结束时刻。中间为公司原动图顶部插画、倒计时和公司红色「立即签到」按钮；宣传二维码不展示。
- 正常状态移除「提前签到，保留本场会议」和具体截止时间两行说明。受保护、观察模式、暂停、缺少释放权限、失联和失败仍显示必要提示。
- 会前倒计时指向会议开始，标题「距离会议开始」，黄色进度条；开始后倒计时指向服务器截止时间，橙色提醒。5+5 分钟规则下分别从 05:00 开始。
- 实际期限服从服务器，不将现有 10 分钟宽限伪装为 5 分钟。后台原有待释放补确认窗口继续保留，`waiting` 状态显示「释放前补签到 · 剩余」，使用 `release_at`；并非前端到零立即释放。
- 截止后停止倒计时和提交入口，等待服务器同步。只有服务器返回 `confirmed` 才显示「已签到」，返回 `released` 才显示已释放。失联、过期、凭证撤销、预约变化仍关闭操作。
- 官方方案继续展示飞书二维码；非业务主控提示到主控门牌签到。模板预览保持只读。
- 日间、夜间及中英文继续支持；减少动画偏好显示静态品牌文字。横屏重点适配 1280×720 和 1280×800，窄屏继续沿用可滚动布局。

## 使用入口与版本关系

V7 是门牌 H5 界面版本；管理 API 和 Android 托管入口继续使用 V6，业务策略 `owner=v5`、API 路径、浏览器存储键、Redis 键均保持兼容。现有 APK 0.7.0 不需要新增原生代码；本轮没有构建 APK；已通过原 APK 完成 W9TW7S 真实配置回执和屏幕检查。

- 独立门牌：`/room-display.html?version=v7` 或 `/?version=v7`，仍需有效设备凭证及签到凭证。
- 旧主控预览版本列表可选「V7 品牌签到」。
- 集中管理：软件模板草稿 → 「门牌界面」选择 V7 → 发布软件版本 → 在设备配置中显式部署该版本。托管终端仍打开 `version=v6&managed=1`，根据已部署 `display_preferences.display_version` 显示 V7；会议室预览同步使用同一版本。
- 5+5 规则：选择 RoomBeacon 签到后，点击「使用会前 5 分钟／会后 5 分钟预设」只设置草稿的提前开放与开始后宽限。选择 V7 外观不会自动改变业务规则，预设也不会改变运行模式、补确认秒数或房间资格。具体日历映射、释放资格和预约核验继续单独管理。

## 兼容与回退

`SoftwareSpec` 与 `DisplayPreferences` 新增 `display_version`，仅接受 `v6`／`v7`，缺省为 `v6`；既有模板无需迁移。设备部署顶层 `config.version` 仍为 `v6`，新增值仅随 `presentation` 下发，不触发 Android 不支持的版本校验。旧管理 API 不增加顶层 V7 枚举。

签到状态响应新增只读 `release_enabled`：结合功能开关、写入开关、房间白名单、策略模式、房间资格与全局暂停。它用于提示，不授予操作权限，也不代替预约核验；缺少该字段的旧后端按未启用释放提示。签到接口、保活协议和释放工作器不变。

回退界面可选择已发布 V6 软件模板版本，按现有部署流程执行；若只需回退外观，应保留相同业务规则。使用 V7 模板的后端不能直接降级到不认识新字段的旧实现，完整服务回退前先恢复兼容模板并核对业务规则和在途状态。本次生产发布的准确 SHA、环境和回退组合见[上线记录](production-v7-2026-09-28.md)。
