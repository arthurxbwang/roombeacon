`roombeacon_checkin` 默认为 true，缺字段的历史配置保持兼容。未签到版必须同时使用 `owner=official`、`mode=off`；服务器拒绝将其与 V5 签到或释放规则组合。这里只管理 RoomBeacon 功能，不修改飞书官方配置。

首次打开管理数据库时，在事务内一次性整理模板：硬件严格匹配已发布型号、固件、尺寸、方向和接线；优先复用正在使用的相同模板及其编号。签到版只复用参数完全一致的正式 V7 发布版本，否则独立建立模板。重复、通用和旧测试模板记为历史选项，默认列表、筛选和新部署选择不显示；勾选“包含历史与已归档”仍可查看。

已发布版本的名称与参数不可覆盖；新日常名称用于台账及选择器，历史详情保留原名。现有设备修订号、配置、会议室软件关联、规则、核验资格、签到记录均不随整理变化。当前使用或明确选择回退的历史模板仍可检查并部署。管理员日后新建模板属于新的显式操作，不由此整理自动部署。

## 删除设备

管理员在“设备台账”点击“删除”，确认框显示设备短码、会议室及后果，再点击“确认删除”。“取消”或“保留设备”不提交请求。只读账号没有删除入口；后端独立拒绝只读操作。

`DELETE /api/v6/admin/devices/{id}` 要求管理员凭证；网页登录同时校验来源和 CSRF。请求体为当前 `expected_revision` 和匹配的 `confirm_code`。修订号冲突返回 409，短码不匹配返回 422，不存在或已删除返回 404。

删除在一个 SQLite 事务内完成：状态记为 `deleted` 并递增修订号，从当前台账移除、清理硬件安装关联；如果是业务主控，清空主控并递增房间修订号，提示重新配置。设备凭证、旧网页会话及旧业务保活身份立即失效；相同旧身份再次注册被拒绝。保留身份占位、配置历史、部署历史、交付证据及可读审计，避免旧应用心跳重新纳管。不会删除会议室、预约或历史签到，不自动替换主控或授予新释放资格。

## 检查与发布边界

验证使用隔离 SQLite、临时 Unix socket Redis 和 mock 外部系统。覆盖模板数与复用、迁移幂等和历史不变、未签到版非法组合及显示偏好传递、管理员／只读／CSRF／来源、短码／修订号、凭证重注册、网页和主控保活失效、历史部署可读、首装不得关联已删除设备；浏览器覆盖确认、取消、冲突、四个选项和未签到版保留官方二维码。

最终后端 411 项全部通过，无跳过；Chromium 151 项全量通过（146 项既有用例及 5 项新增用例），npm ci、类型检查／构建、Ruff 0.16.7 和 `git diff --check` 通过。Android 源码与 APK 未变更，本次没有新增实机验收。

上线需要另行确认准确应用提交、生产目标与回退。部署前私密备份管理 SQLite，记录当前选中模板、关联、策略及设备回执；上线后先核对两类模板各 2 项及 BDC5ZS 配置不变，再由管理员确认是否删除 W9TW7S。

模板整理回退只撤销历史选项标记、恢复草稿名称；不能改写发布版本或整库覆盖后来变更的账号、设备及业务状态。实际删除后不直接回退不理解 `deleted` 的旧后端：旧台账会重新显示占位且旧管理操作可能重新激活它；须保留删除兼容补丁。删除后的终端若需重新交付，应使用新身份重新注册、核对短码并显式部署。
