## 3. 已实现与未实现

### 已实现

1. H5 V1/V2/V3 可切换；默认 V2，显式 `/?version=v3` 使用最新设计。
2. 中控 `/control` 登录、地区/名称筛选、上一间/下一间、全屏、自动/日间/夜间预览。
3. 飞书后台批量采集，HTTP 终端请求只读缓存；旧快照保留 7 天。
4. 日历预约状态、组织者及可见主题；并非传感器判断真实人数。
5. V3 官方扫码签到入口、美术二维码及公司品牌动画。不会调用签到 API，不显示虚构“已签到”。
6. 主控两组独立凭证，主组 >=32 字符，第二组允许非空短密码；修改服务器配置后重启生效。
7. CLI 表格列表、地区筛选、分页、设备凭证签发/撤销。

### 必须保留的边界

- 单房间设备凭证有效 30 天，重新签发会使同房间旧凭证失效；多终端共用该房间凭证的现状尚未升级成逐设备身份。
- 浏览器只把绑定和版本持久保存。日程快照在页面内存中，重启或清除页面后离线恢复尚未实现。
- 手机飞书扫码结果以官方页面为准；尚未验证存在公开“直接设为已签到”接口。
- 北京 205 曾配置官方二维码，配置按唯一 room_id 区分，南京同名会议室不能共用；真实链接 resource_token 留在服务器配置，不写文档。
- 未识别城市显示“城市待配置”；中控可手动预览主题，但持久编辑城市功能尚未实现。
- 原生 APK、Device Owner 锁定、ESP 固件、灯带控制、OTA、终端本地持久缓存均未实现。
- `meeting_room_events.py` 和按需 `schedule_for` 作为原有可测试辅助逻辑保留，但独立入口不启动 WS，也不调用按需日程查询。后台采集是当前生效路径。
- 旧平台 `/meeting-rooms` 管理路由及权限体系不迁入运行程序，其源码/测试以文本归档。凭证继续由 CLI 管理。
