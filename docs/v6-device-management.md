# V6 集中管理与免配置门牌

更新：2026-09-22。需求 [#10](https://github.com/arthurxbwang/roombeacon/issues/10)，决策见 [ADR 0004](adr/0004-v6-managed-devices.md)。用户已确认完成飞书应用回调配置，追加要求首页飞书登录及一次性首位员工管理员初始化，见 [#17](https://github.com/arthurxbwang/roombeacon/issues/17)。

## 功能与使用

普通首页 `/` 进入 V6 后台 `/control`，只显示飞书扫码/快捷登录；带 `version` 或 `managed` 参数的根地址以及 `/room-display.html` 继续显示门牌。`/control/legacy` 保留旧主控页面，既有主控凭证API保留应急及兼容用途。飞书登录入口跳转官方授权页，扫码或客户端授权后返回，会话8小时。新用户默认待授权，仅本次明确启用的初始化会将首位通过企业成员核验的员工设为管理员。已有管理员在「账号权限」授予管理员或只读权限，改权后原会话撤销，用户重新登录。只读账号能查看设备、会议室、模板、配置历史和审计，不能认领、发布、刷新、改权或调用旧 V5 写接口。

Android 0.6.1（V6，versionCode 8）默认直连 `https://roombeacon.thundersoft.com`。启动并联网后显示原生待部署页，自动注册，六位唯一码按 `ABC 234` 显示。后台可用唯一码、SN、MAC 和会议室搜索，管理员认领时选择已激活状态与会议室。新设备无需输入维护密码、服务器或房间令牌。已验证型号允许普通应用只读 `/sys/class/net/{eth0,wlan0}/address` 时补充真实 MAC，过滤系统占位值；其他型号不扩大读取路径。MAC/SN 未获系统许可时明确显示「系统未提供」，不伪造硬件标识。

Wi-Fi 和 Ethernet 都通过 Android 默认网络访问服务，分别上报接口 MAC 和地址；PoE 供电的设备按有线网络处理。切换网络不变更设备 ID。SN、MAC、短码均非秘密凭证，不自动据此继承旧设备权限。重装或清除数据后需要后台重新确认资产关联。

「配置」支持显示版本、方向、灯控、会议室变更、停用和撤销；模板用于批量发布非房间设置。期望版本与实际应用版本分别显示，失败回执单独提示；历史已激活配置可以发布为新版本回退。远程刷新通过新配置版本触发。原生配置更新通常在 15 秒轮询后接收，后台下一轮刷新显示回执；不保证离线设备立即收到。

V6 页面根据服务器房间 owner 自动采用官方签到或 V5 确认使用，不改变房间写入白名单或提前结束关闭状态。设备管理心跳不代替网页主动 V5 心跳；配置版本变化使旧网页会话失效，原有预约保护不重置。

## 认证、存储与接口

- `ROOM_DISPLAY_V6_DB`：独立持久 SQLite 路径，单主写入，WAL、事务与版本冲突保护。目录只允许运行用户访问，数据库及 WAL 不得纳入静态资源。
- `ROOM_DISPLAY_PUBLIC_ORIGIN`：唯一可信后台 HTTPS origin。
- `ROOM_DISPLAY_FEISHU_LOGIN_ENABLED`：控制飞书登录入口；`ROOM_DISPLAY_FEISHU_TENANT_KEY` 可限制企业。
- `ROOM_DISPLAY_FEISHU_BOOTSTRAP_ADMIN_ONCE`：默认false，仅按明确授权开启。SQLite事务内唯一选举，`meta.feishu_first_admin`记录消费结果，`meta.feishu_login_tenant`固定企业。成功一次后，即使开关仍为true、服务重启或管理员停用，也不会再自动授予权限；已有管理员时跳过并永久消费。首次员工使用应用企业令牌查询通讯录核验，失败不消费名额。禁止删除消费记录来重开初始化。
- `/api/v6/auth/*`：认证引导、浏览器会话和账号角色。Cookie 为 Secure/HttpOnly；写操作验证 CSRF 与来源，OAuth state 绑定浏览器、单次消费。
- `/api/v6/device/enroll`：受限引导，设备自行生成的独立凭证只能建立待激活记录。每来源限流，最多500条待激活，身份已存在必须匹配原摘要。
- `/api/v6/device/sync`：认证后报告网络/软件/配置回执，获取期望版本及短期网页会话。管理凭证在 Android Keystore 加密保存，不进入 WebView。
- `/api/v6/admin/*`：设备、历史、回退、批量配置、模板、审计与节点能力描述。修改必须管理员身份。
- 新网页会话仅允许既有展示及 V5 设备操作 API，不允许后台管理。撤销/换房/配置版本变化立即拒绝旧会话。后台只保存原生凭证摘要。

当前节点只有 `central`；协议包含 node_id、版本、配置回执，拒绝未知节点。不接受任意服务器地址，不提供尚未实现的异地节点管理按钮。地区节点同步、离线授权租约和自动切换未来另行实现。

## 飞书应用配置与真实验收

1. 在现有灯塔应用的安全设置添加 `https://roombeacon.thundersoft.com/api/v6/auth/feishu/callback`。
2. 确认网页应用及登录人员可用范围，按飞书要求发布配置。
3. 用户已确认回调配置完成。本次首位成功登录且通过企业成员核验的员工自动成为唯一初始管理员；后续员工待授权，管理员在账号权限页处理。首次员工须在现有通讯录读取范围内，不能通过忽略核验错误授予权限。

本轮具备代码与隔离联调，不把尚未完成的真实扫码视为验收通过。

## 安装与运行边界

测试期沿用当前调试包名与签名升级，既有网页数据保留但 V6 以后台分配为准。普通 APK 不承诺安装完成即自动弹出；安装工具负责首次启动，默认桌面或厂商方案负责开机进入。已有 Device Owner 时应用设置专用 HOME 和锁定；本次不擅自恢复出厂或赋予 Device Owner。

网线实际插拔与 PoE 供电需要现场硬件；软件接口模拟或看到 eth0 不等于 PoE 实机验收。无入站维护端口和常规本地设置入口，完全断网或身份损坏需受控 USB/厂商维护。

## 发布与回退

服务器从 GitHub 准确 SHA 检出，使用 `scripts/production/deploy-v6.sh SHA` 构建与验证。部署前记录旧后端链接和 Nginx 配置，备份 V6 数据库（如存在）及配置。新配置写入共享目录，不清空 Redis，不轮换旧房间凭证。服务重启会触发既有 V5 重启保护。

失败时自动恢复旧后端和 Nginx；手动回退也使用对应备份目录的 backend.before、nginx.before 与 dropin.before。保留新增设备台账，不恢复旧格式 V5 记录，不把受保护预约重新放行。设备 APK 回退使用安装前保存的旧包，保留原网页数据。

具体发布 SHA、测试计数及样机结果见 [V6生产验证记录](production-v6-2026-09-22.md)。
