# ADR 0005：硬件安装模板、软件模板与会议室部署

2026-09-24；已采纳。需求与实施跟踪：[Issue #27](https://github.com/arthurxbwang/roombeacon/issues/27)。

## 决策

设备是部署入口。每台设备关联一个明确版本的硬件安装模板；每间会议室关联一个明确版本的软件模板，同一房间的多台设备共用软件规则，每台保留自己的硬件安装参数。房间可以没有设备，仍显示在完整会议室目录。V5 房间指定一台业务主控，其余设备仅展示，不能签到或发送健康确认。

硬件模板保存型号、固件、安装方向、物理分辨率、灯控开关、GPIO 与点亮电平。软件模板保存布局、方向和最小网页尺寸要求、背景、语言、日夜模式及 V5 提前开放、开始后宽限、补确认参数。房间的官方规则核对、释放验证与预约逐实例授权不属于模板，不能批量复制。

草稿保存、发布版本、部署分别操作。已发布版本不可覆盖；编辑或发布不会自动更新现有设备。部署引用具体版本、设备及房间修订号，预览范围并显式提交；同房间换软件必须确认影响其他设备。批量操作为一个 SQLite 事务，设备应用异步并逐台显示回执。

## 数据和接口

新增 `config_catalog`、`config_versions`、`hardware_tests`、`room_configurations`、`device_installations`、`configuration_deployments`、`configuration_assets`。保留原设备、凭证、历史模板、Redis 与 API 路径。

- `/api/v6/admin/catalog`：新建、编辑、发布、归档及硬件测试记录。
- `/api/v6/admin/configuration`：设备、会议室、版本与部署交叉查询。
- `/api/v6/admin/deployments[/preview]`、`deployment-batches[/preview]`：单设备及批量部署。
- `/api/v6/admin/devices/{id}/adopt`：将历史实际参数转换为明确模板关联，不改变设备身份、绑定、配置或修订号。
- `/api/v6/admin/rooms/{room_id}/qualification`：仅更新该房间核验记录，有独立版本检查。
- `/api/v6/admin/assets`、`/api/v6/assets/{id}`：有限大小同源 PNG；管理员或绑定该资源的设备才能读取。

新接口沿用管理员、只读及 CSRF 认证。已转换设备不再通过旧配置或旧回退接口写入；刷新仍可使用原接口。未转换设备维持兼容。旧房间规则入口不能覆盖已经由软件模板管理的参数。

## 生效与失败

设备目标配置和模板引用一起提交；设备报告修订号及错误后才判断应用。房间规则异步同步到 Redis，保持现有核验资格；自动释放缺资格时标记阻塞。改变 V5 规则前等待主控应用配置，配置一致时不重写策略版本。失败、部分生效、等待应用、被后续部署替代分别展示。远程刷新不改写原部署快照。

Android 0.7.0 上报协议 3、屏幕物理尺寸、网页尺寸和像素比，支持固定夜间和受控 GPIO 接线。当前原生驱动只允许已支持的 147、148、154 三个 RGB GPIO 互换及 0/1 电平；不开放任意引脚。协议 2 仍支持已有接线，不能应用自定义接线。模板记载的物理尺寸与软件网页尺寸分别展示，不能互相冒充。

## 迁移与回退

首次打开新版本仅新增表、内置硬件版本和待核对的历史草稿，不批量重发配置。历史关联需显式转换，不能仅凭参数相似猜测使用关系。同房间历史显示参数不一致会报冲突，须核对后统一。

应用发布保存准确 Git SHA、SQLite 一致性备份和旧 APK。应用版本回退保留新增表及账号／身份记录；已经部署新配置时，先在新管理界面选择兼容旧 APK 的模板版本组合恢复，核对设备回执，再回退服务或 APK。不能直接还原整库覆盖后续账号和业务状态。

## 验证边界

隔离回归覆盖授权、并发冲突、迁移不变性、多设备关联、规则资格、PNG 访问及设备能力。浏览器覆盖编辑、发布、部署、批量、三级反查及只读模板预览。真实生产验收不增加、删除、修改飞书会议室或预约，不执行签到或释放。硬件测试记录表示人工登记的实际测试证据，模板发布本身不代表硬件已实测。
