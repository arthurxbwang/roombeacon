# ADR-0001: 门牌独立维护为 RoomBeacon

> 状态: 已采纳（本地代码迁移，部署另行执行） | 日期: 2026-09-16 | 决策者: 项目负责人

## 背景

用户已建立独立仓库并授权跨项目迁移，明确 Argus 后续不维护本项目。已有独立服务只需要飞书应用和本机 Redis，未来增加 Android 与 ESP 终端。

## 决策

选择性抽取可运行独立子系统，保留来源 SHA/文件哈希和设计交接。不导入整个 Argus 历史、不携带密钥，不修改线上部署。Python/Vue 技术栈保留，精简配置、前端登录依赖与飞书客户端。

## 后果

### 正面

后续开发与审计在一个独立仓库完成；不依赖 Argus 数据库与用户登录；能独立构建和测试。

### 负面

源仓库 Git 历史只以出处和提交列表追溯；旧平台专属管理路由不在新程序中，CLI 继续负责凭证管理；发布切换需要单独协调。

## 备选方案

### 方案 A: 全量复制 Argus

优点是无需裁剪；缺点是无关代码、依赖和权限边界继续耦合，不符合用户独立维护目标。

### 方案 B: 重写门牌

优点是重新组织接口；缺点是破坏已确认 UI 与增加回归范围，本次不采用。
