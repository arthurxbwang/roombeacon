# ADR 0003：V5 确认使用与受控释放

- 日期：2026-09-20
- 状态：已实施本地版本；真实预约验收与发布待执行。

## 背景

用户批准在不影响当前测试与使用的前提下迭代 V5。飞书公开的会议室实例回复接口支持未签到释放与提前结束，但不提供文档明确的「已签到」写入状态。忙闲快照不能可靠区分普通与重复会议。

## 决策

1. V5 通过 `?version=v5` 显式进入，默认仍为 V4；中控预览选择 V5 不覆盖既有版本偏好。APK、真实样机入口及既有构建产物不随本次本地实施更新。
2. 原有展示 API 与凭证保持只读。V5 使用独立 `usage:omm_ID:random` 操作凭证和独立缓存 API，不把写权限追加到旧凭证。
3. `ROOM_DISPLAY_USAGE_ENABLED` 与 `ROOM_DISPLAY_USAGE_WRITES_ENABLED` 默认均为 false。仅启用前者可运行确认和观察；飞书写入还需房间自动模式、原生策略核对、接口验证、单次预约登记及全局解除暂停。
4. 无人员登录的门牌只能证明持有操作凭证的终端确认过，不能证明具体参会人的身份或飞书原生签到状态。
5. 现阶段为有限范围试点：只有管理员明确核对的非重复单次预约才可释放。不能凭 original_time=0 自动放行，也不能因为开启房间自动模式就放行所有预约。
6. 任务通过 Redis 租约选举单个工作进程，以 CAS 原子转换抢占操作；飞书写请求仅发送一次。请求超时、进程取消或未知结果均不自动重发。
7. 工作者须在确认窗口开始前持续运行，设备心跳有效；确认记录缺失、登记标记已存在、监控中断或任期改变时暂停释放。确认成功后仅从缓存读取，不以设备本地点击记录代替服务器确认。GET 不产生心跳；协议 2 由实际页面上报会话及操作状态，提交中／未知结果不能作为可释放证明。
8. 释放前查询上游并核对实例、房间、时间和当前策略，释放后再次核验。飞书写入和本地 Redis 不构成事务；上游改期与释放之间的竞争无法完全消除，试点验收需覆盖该边界。
9. 释放成功时让旧快照过期，等待现有采集器回填，不构造空闲日程。故障或网络未知时维持状态待确认，侧灯沿用原有未知状态规则。
10. V4 与 V5 按服务器端 owner 隔离；官方方案关闭本系统操作，V5 必须由管理员核实本房间原生未签到释放已关闭。页面版本参数不能切换后台责任，V5 不混用官方二维码。旧无 owner 的策略按官方关闭处理。
11. 未确认到期后默认等待 60 秒供补确认，再要求当前页面在 15 秒内回复一次核验；提前结束也需核验。绑定实例、策略、工作者任期和页面会话，发送前重查有效期。常见故障跳过本次，不追补；保留已发出请求无法撤回的边界，不引入跨系统事务。

12. 服务器释放白名单默认空；仅精确匹配配置房间 ID 才有写入资格。即使其他房间误配置为自动模式，任务与提前结束仍被阻止。主控不能扩大白名单。

## 影响

- 增加专门的 V5 API、工作任务、Redis 状态与审计；所有新接口仍要求相应设备或主控凭证。
- Redis 确认记录、策略和解除暂停状态目前保留 7 天；策略过期回到关闭，暂停记录过期回到暂停。操作审计保留至多 30 天、每房间及全局各最多 1000 条，查询最近 100 条。每 2 秒监控续期不写审计。
- 观察模式不会调用飞书释放；默认配置不启动 V5 工作者，旧展示请求不增加 V5 Redis 或上游调用。
- 真实 P0 预约及重复实例验证尚未执行，默认开关保持关闭，不将隔离测试宣称为线上验收。
