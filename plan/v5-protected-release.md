# V4 官方签到与 V5 保护释放实施计划

更新：2026-09-20。状态：用户授权连续开发测试后，方案隔离、操作异常保活、待释放补确认及发送前核验已本地实现。本文保留目标设计和验收步骤，实际结果见 [V5 说明](../docs/v5-usage-verification.md)与[专用房间记录](../docs/v5-test-room-verification.md)。尚未部署，真实预约准备受应用权限阻塞。本计划取代[上一版计划](checkin-release-iteration.md)中的双方案切换、故障处理和试点安排；原接口调查保留为背景。

## 1. 两套方案的边界

| 项目 | V4：飞书官方签到 | V5：RoomBeacon 确认使用 |
|---|---|---|
| 用户操作 | 扫飞书官方二维码 | 在平板点击「确认使用」 |
| 确认结果 | 由飞书处理 | 由服务器保存，不写成飞书已签到 |
| 未签到自动释放 | 按该房间飞书后台规则执行 | 该房间飞书原生未签到自动释放必须关闭，由服务器判断 |
| RoomBeacon 写入 | 不执行确认或释放 | 符合条件才释放本次会议室预约 |
| 故障处理 | 官方流程保持原样 | 检测到异常则保留预约、跳过本次自动释放 |
| 页面 | 保留官方二维码 | 移除官方签到二维码，展示确认、截止及异常状态 |

两套方案按会议室选择，同一房间不能同时运行两套自动释放判断。关闭飞书规则仅针对 V5 房间，不全局关闭 V4 房间的规则；飞书后台能否按测试房间独立配置，须在准备阶段核对。这里只关闭原生「未签到自动释放」，不取消预约能力或管理员正常管理权限。

服务器保存房间采用的方案，是释放权限的依据。`?version=v4/v5` 只选择界面，不能借此启停后台任务；页面与房间方案不一致时提示管理员，不展示误导性的签到入口。默认仍为 V4，中控预览只读，现有房间不自动迁移。

业务可靠性目标：覆盖断网、页面卡死、确认请求失败、服务重启和 API 不可用等常见故障。不新增多机共识、跨系统事务或自动恢复已释放预约。接受请求已经发出后才发生故障所留下的少量结果不明情况，保留审计并人工核实。

## 2. V5 正常流程与时间参数

1. 服务器在完整确认窗口开始前运行，登记本次预约；平板进入 V5 并持续同步。
2. 开始前 5 分钟开放确认，开始后 10 分钟为正常确认截止时间。确认以服务器保存成功为准。
3. 截止仍未确认，进入 60 秒「待释放」阶段。平板提示「尚未确认，即将释放」，仍允许补确认。
4. 服务器在准备发送前向实际签到页面发起本次预约的状态核验；页面须在 15 秒内回复，且不存在提交中或结果不明的确认操作。
5. 核对预约、确认记录、房间方案、释放开关、工作者租约和上游查询，原子认领后发送一次释放请求。
6. 查询飞书忙闲验证结果，再由正常采集刷新页面。释放结果不明时显示待核实，不自动重发，也不直接显示空闲。

建议沿用 10 秒心跳、45 秒失联阈值。60 秒待释放和 15 秒核验期限为新增建议参数，先在虚拟房间调整，不直接用于现有房间。所有期限由服务器判断；核验完成后、请求发送前再次检查其有效期。会议已经结束则不再释放。

待释放期间补确认成功，立即取消候选释放；若服务器已认领释放，则明确提示处理中，不返回虚假的确认成功。临界时刻由原子状态转换决定先后，不承诺外部 API 与确认操作完全原子。

## 3. 保活与故障保护

### 平板

- 心跳由实际签到页面产生，包含页面会话、本次预约、策略版本及操作状态。页面挂起或卡死不能由另一个后台进程代报正常。
- 将查询状态与「允许释放的健康回报」分开；现有 GET 查询成功不能自动算作可释放。新增的健康上报和核验回复同样使用独立 V5 操作凭证，校验房间、会话和时效。
- 点击时立即置为提交中，并保存最小待核实标记；只有服务器返回成功才显示已确认。提交超时或失败后继续查询结果，但不再回报可释放。
- 服务器一旦收到操作异常状态或发现失联，将本次实例置为保护状态；恢复网络只恢复显示，不重新自动释放该实例。
- 页面刷新或重启后先核对服务器状态和待核实操作；新会话不沿用旧会话的核验回复。试点每间房绑定一个有效操作会话，其他窗口不能替失联平板提供健康证明。

### 服务器

- 保存确认记录及审计，沿用原子状态转换、工作者租约、策略版本和独立操作凭证。
- 重启、监控中断、缓存过期、记录缺失、凭证撤销、方案变更或平板故障时，跳过受影响会议的自动释放；不在恢复后补发。
- 只有完整监控的实例才有自动释放资格。确认窗口中途恢复的会议仍可保留预约；下一场完整窗口重新开始自动管理。
- 待释放核验绑定房间、实例、策略版本、工作者任期和当前页面会话，使用短期且一次性的核验标识；旧响应不能授权下一场释放。
- 发送前重新检查确认状态与暂停开关；中控保留全局暂停、逐房间关闭及原因查询。提前结束仍需二次确认及当前状态核验，不绕过房间方案和写入开关。

### 飞书 API

- API 由服务器访问，平板只与 RoomBeacon 通信。复用正常采集和释放前只读查询，不增加每台平板直接探测飞书的流量。
- 释放前查不到目标预约、请求失败、限流、授权失效或数据无法核对时，跳过本次自动释放。
- 只读成功仅证明本次读取可用，不证明写权限或下一次写入必然成功。权限和实际释放能力在专用预约中验收。
- 写请求仅发送一次；超时或进程中断后结果未知，记录待核实，不盲目重试。已发出的请求不能由故障保护或回退开关撤回。

用户创建一间独立、可预约的测试资源，建议名称「RoomBeacon-V5-测试（非实体会议室）」。不使用北京 201、205 或其他正在使用的房间。

- 记录准确房间 ID、时区和名称，确认应用能够读到该资源。

测试环境准备独立构建、配置及隔离 Redis，写入范围只放行该测试房间和已登记预约。若使用现有样机临时测试，先保存绑定并安排明确测试时段，结束后恢复；优先使用独立浏览器或备用平板，避免影响当前使用。

## 6. 实施和测试顺序

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| A：准备，可与 B 并行 | 用户创建虚拟房间；核对官方规则和测试环境 | 房间可读、规则独立关闭、非重复预约及允许释放范围明确 |
| B：本地改造 | 方案隔离、操作异常保护、待释放和状态核验 | mock 故障测试及 V4 回归通过，写入默认关闭 |
| C：虚拟房间观察 | 接入实际平板／浏览器，只确认与记录候选释放 | 刷新恢复、心跳、故障保护正确，没有业务写入 |
| D：虚拟房间写入 | 放行专用预约，依次验证释放、保留、提前结束及异常 | 目标资源变化正确，范围和通知可解释，其他房间不受影响 |
| E：回退演练 | 暂停 V5，核对在途请求，测试切回官方方案 | V5 不再写入，测试房间官方入口及规则核对完成 |

阶段 D 不要求先等三个工作日；可用多场短测试预约完成流程验证。真实业务房间推广另行选择试点和观察时长，本轮不自动扩展。

### 必测用例

| 场景 | 预期 |
|---|---|
| 正常点击确认；重复点击；刷新页面 | 同一预约确认一致，不触发未确认释放 |
| 一直不确认，三方正常 | 完成待释放及核验后释放一次，核实可重新预约 |
| 待释放期间补确认 | 保存成功即取消本次候选释放 |
| 确认 POST 失败，但 GET 和心跳通道仍可用 | 不允许 GET 掩盖故障；本次受保护，不自动释放 |
| 确认已保存但响应丢失 | 查询恢复已确认状态，不释放 |
| 平板断网、断电、页面卡死或后台挂起 | 到期无新鲜核验回复，不释放；恢复后不追补 |
| 服务器重启、卡顿跨过核验期限、Redis 不可用或记录丢失 | 不使用旧核验回复，本次跳过；下一场完整窗口可恢复 |
| 飞书读取超时、限流或权限错误 | 不发送释放；显示原因 |
| 飞书释放明确失败或响应丢失 | 失败或待核实，不重复写、不误报空闲 |
| 预约改期、取消、会议结束、撤销凭证或切换方案 | 旧实例和旧核验回复不能释放新预约 |
| 旧 V4 客户端、多个页面、过期核验回复 | 无法代替指定 V5 会话授权释放 |
| 手动提前结束 | 二次确认后仅影响指定预约资源 |
| V4 回退及其他房间对照 | V5 写入停止，其他房间的官方流程和绑定不变 |

断网、断电及进程故障只在隔离测试环境执行；复杂错误响应通过 mock／隔离代理注入，不修改公共网络或共享服务。重复会议继续排除，待单实例影响范围验证后另做支持。

每项保留预约标识、计划时间、操作及服务端审计、API 脱敏结果、飞书忙闲变化与通知现象。区分 mock、浏览器和实机结果，不把模拟通过当成真实验收。运行 Ruff 0.16.7、pytest、隔离前端 npm ci/build/Playwright 和 git diff --check；若改 Android 再执行原生完整检查。

## 7. 发布与回退

开发与隔离测试已实施，尚未部署、修改飞书后台规则或调用真实释放。发布明确目标服务、准确 SHA、配置和回退版本，经 GitHub 管理源码，不从开发机复制源码到服务器；不默认部署旧服务器。

V4 转 V5：暂停 RoomBeacon 写入 → 关闭并核实目标房间官方未签到释放 → 配置 V5 和有效平板会话 → 观察 → 对后续完整确认窗口启用自动模式。不要在会议中途切换释放责任。

V5 转 V4：暂停目标房间 V5 写入 → 核对并处置在途／结果不明操作 → 切换服务器方案和 V4 页面 → 恢复该房间原有官方签到规则并验证。页面切回 V4 本身不会恢复飞书后台规则；只需紧急止损时，暂停 V5 后可先保留预约，不急于开启官方自动释放。

保留确认和审计数据，不清空 Redis、不轮换其他房间凭证。代码回退不能恢复已经释放的预约；有需要时由管理员核对冲突后处理，不自动重新占用。
