## 1. 本轮确认与目标

- 用户确认拟交付设备均支持 PoE 供电，接受通过供电中断后重新上电恢复设备的方向。交换机的可管理性、型号、端口供电控制及设备实际断电恢复仍待核实。
- 新设备现场手动联网，取得 IP；用户说明出厂网络 ADB 默认开启。新批次仍需确认端口、首次授权或配对要求，不从现有样机推断全部固件一致。
- 后台录入 IP 后安排首次 APK 安装，设备自动注册；核对设备身份、分配房间及模板，验收后关闭网络 ADB。首版允许人员用厂家工具手动关闭。
- 业务、布局和签到交互继续通过 H5／服务端更新；APK 作为低频维护底座，保留必要升级能力。系统 WebView 和厂家固件独立维护。
- 用户在保存计划后要求实施，随后明确要求部署后台并测试；PR #44 已合入并由生产从 GitHub 部署 `3d0542d`。真实页面和接口检查通过，未安装 APK、关闭 ADB 或操作 PoE，见[发布回执](../docs/production-installation-2026-10-08.md)。

## 3. 首批交付动线

`上电联网 → 导入 IP → 探测与安装 → 首次启动／自动注册 → 核对短码并贴标 → 分配房间与模板 → 实机验收 → 关闭 ADB → 断电恢复复验 → 完成交付`

| 步骤 | 人员操作 | 执行结果与完成条件 |
|---|---|---|
| 到货登记 | 建立设备清单，接电、联网 | 记录型号、固件、内存、屏幕和资产标识；检查生产域名、DNS、时间和 HTTPS |
| 导入与探测 | 后台粘贴 IP 或导入清单 | 执行端确认网络可达、ADB 可用及授权状态；读回硬件与已有 APK |
| 首次安装 | 选择已批准 APK 版本并提交任务 | 验证包名、签名和文件完整性；逐设备安装、首次启动、记录结果 |
| 设备关联 | 核对屏幕短码、SN 与实物，贴标签 | 首装任务关联注册设备 ID；无法唯一匹配时等待人员确认 |
| 房间配置 | 选择会议室及已发布硬件／软件版本 | 复用现有部署与回执；批量处理前展示实际影响设备和房间 |
| 实机验收 | 检查房间名称、显示方向、画面、灯色 | 身份、配置回执、页面加载和新鲜业务数据分别正常；首次断电恢复通过 |
| 调试关闭 | 首版手动关闭；后续可确认交付后自动关闭 | 核对实际网络 ADB 不可连接，同时 HTTPS 管理、业务页面和回执正常 |
| 关闭后复验 | 对目标端口断电再上电 | 无 ADB 条件下自动恢复；重启后 ADB 仍关闭，身份、房间、页面及灯控保持 |
| 交付归档 | 确认结果并移交 | 保存发布版本、验收记录、安装位置、交换机与端口映射、维护入口 |

失败设备单独进入待处理列表，批次内其他设备可继续。安装成功不能直接标记“已交付”；现场画面未核对、关闭状态未知或断电恢复失败均不通过交付。

会议室采用官方扫码或 RoomBeacon 签到需另行核对业务设置。官方方案必须配置真实官方签到链接；安装 APK 不会自动生成来源链接。模板部署不复制其他房间的释放资格或扩大写入白名单；未来预约仍按原有逐实例规则核验。

## 4. 后台、现场安装助手与门牌前台

### 管理后台

在现有设备、会议室、模板和审计能力上增加以下入口，不重复建立另一套配置台账：

| 页面／入口 | 操作和状态 |
|---|---|
| 批量交付 | 导入设备 IP／清单，选择安装执行端及 APK；按设备查看探测、安装、注册、配置、验收进度 |
| 设备详情 | 展示短码、SN、最近 IP、网络、APK／H5／WebView／固件版本、期望与实际配置、页面健康 |
| 交付验收 | 记录现场画面、灯色、开机恢复、ADB 关闭及关闭后 PoE 恢复结果；人工核验与自动回执明确区分 |
| APK 发布与更新 | 发布版本和适用型号、选择试点、提交更新任务、查看安装结果及升级后健康 |
| 维护任务 | 页面刷新、配置回退、维护状态和历史记录；具备已核验端口映射及连接器后提供单端口电源恢复 |

页面采用人员可理解的状态，例如“等待联网”“等待设备授权”“安装完成，等待注册”“等待房间分配”“配置待应用”“等待现场验收”“关闭状态待核验”“已交付”。只读账号只能查看；管理员提交动作，服务端校验权限、目标范围和当前状态。

### 现场安装助手

- 优先运行在与设备网络互通的现场电脑；后台通过已认证 HTTPS 分配任务，助手只处理该次明确选择的设备。生产服务器可达设备时，可部署独立执行端，能力与现场助手一致。
- 浏览器页面负责发起任务和显示结果，实际 ADB 由执行端运行。不要把任意 shell 命令作为后台接口，也不要求生产服务器与全部设备的 ADB 网段互通。
- 2026-10-10 #70／PR #71已取消首装IP／网段名单，上线准确应用 `35ca0d9`。后台和新版现场助手支持任意站点的RFC1918内网IPv4，无需逐站点扩名单；实际检测 `10.0.51.170` 返回200，但已有门牌应用，仍须核对短码和配置。跨站点路由与实机交付单独验收，见[上线回执](../docs/production-install-no-allowlist-2026-10-10.md)和[操作说明](../docs/installation-delivery.md#跨网段与跨站点安装)。
- 首版可先交付批量安装工具和结果清单；随后接入后台任务。电脑操作系统、批量规模和网段由实施前的现场信息确定。
- 每台设备任务独立、可恢复；限制并发与超时，重试前核对实际版本，重复提交不盲目重装。切换执行端需要重新确认设备授权。
- IP 为连接定位；关联采用设备 ID／短码及实物核对，SN／MAC 仅作辅助。地址变化或复用不得使任务安装到另一台设备。
- 结果只回传必要版本、错误类别和任务证据；不收集设备身份凭证、管理员密码或完整网页会话。

### 门牌前台与现场维护

- 保留联网后的短码及待部署页，成功配置后进入业务门牌；正常显示不堆叠安装和运维信息。
- 硬件功能、安装与调试开关由原生或厂家服务执行；不向 H5 开放任意命令、安装任意文件或控制交换机的接口。
- 后续提供经过认证的本地维护状态，明确进入、退出及升级中行为。具体入口、认证方式与超时在 #29 实施前确定；首版继续使用厂家工具。
- 现场人员手动开启 ADB 后，不因心跳或 Activity 恢复立刻被关闭；维护结束再关闭。断网、撤销或服务器故障不自动打开 ADB。

## 5. H5 为主、APK 低频更新

- H5 与服务端承载业务和布局；硬件、软件模板按 [ADR 0005](../docs/adr/0005-versioned-configuration.md) 发布与部署。稳定协议兼容旧 APK，服务端不能要求全部设备随业务版本同步升级。
- 正式批量交付前固定正式包名、发布签名、APK 版本和适用型号。当前调试包与正式包属于不同安装身份，迁移单独设计，不默认覆盖或卸载旧包。
- APK 更新仅用于原生认证、恢复、硬件适配、厂家接口或原生缺陷；WebView、系统与固件版本分别记录和维护。
- 后台指定目标版本，设备通过认证 HTTPS 获取任务；设备验证包名、签名、版本、来源与完整性，再调用安装能力。更新失败保留原有可运行版本，不能靠卸载或清数据恢复。
- 优先验证匹配固件的厂家 `silentInstallApk`。必须以 RoomBeacon 普通应用身份验证权限、安装结果和升级后启动；厂家返回 true 不等于安装完成。若不可用，再评估受管设备安装或现场确认方案，不默认获得 Device Owner 或系统签名。
- 更新先单台试点再扩批；维护期间明确业务不可用状态，避开在途签到／释放，升级后核对设备身份、房间关联、实际 APK 版本、页面及灯控。安装动作与最终健康分开回执。
- APK 回退不能假定 Android 允许低版本覆盖；优先 H5／配置回退，原生故障按签名和数据兼容性制定修复发布或受控恢复方案。长期目标为无需重新打开网络 ADB 即可完成 APK 维护。

## 6. 分层恢复与 PoE 电源操作

| 层级 | 故障及恢复 | 当前边界 |
|---|---|---|
| 页面 | 加载失败重试、渲染进程退出重建 WebView | 已有实现；主线程卡死时，同线程定时器不能自救；DOM 有响应不代表数据新鲜 |
| 应用 | APK 退出／无响应时拉起或恢复 | 优先核对厂家启动和守护服务，分别验证进程退出与无响应；尚未完成此验收 |
| 系统 | Android／内核卡死后的硬件恢复 | 向厂家确认硬件看门狗及实际触发条件，不从系统功能名称推断能力 |
| 外部供电 | 由门牌以外的管理路径切断再恢复 PoE | 设备支持 PoE 已由用户确认，交换机控制和实机自动恢复待完成 |
| 现场 | 交换机管理也不可达、硬件故障、身份损坏 | 保留人工供电及厂家／USB 维护流程 |

PoE 操作的首选为**指定端口关闭供电后再恢复供电**，逐台处理并记录结果。整台交换机重启仅作为人工恢复手段，执行前明确受影响的全部终端和网络设备。

**交换机重启不等于门牌实际断电**：部分交换机会保持 PoE 输出；禁用数据端口也未必关闭供电。先验证目标型号真正切断电源、重新上电与可观测状态，再纳入标准流程。另有 DC／USB 供电时必须核对是否仍维持设备运行。

交换机连接器实施前必须确定：

1. 管理型交换机型号、固件、支持的管理协议和独立管理访问路径；门牌离线时执行端是否仍能连接交换机。
2. 设备→交换机→物理端口的唯一映射；由接线清单及现场验证确认。仅凭 IP、未验证的 MAC 学习结果或猜测不能断电。
3. 供电关闭／恢复的状态读取、间隔、超时与失败处理；具体值依据交换机和门牌试验确定，不写死未经验证的时长。
4. 先安排可靠的恢复供电步骤；关闭后任务失败、执行端退出或网络中断时，必须有交换机侧能力或独立执行保障恢复供电，并保留现场补救。
5. 管理员权限、实际影响范围预览、维护原因、审计及重试限制；首版只由人员明确触发，不因一次心跳丢失自动断电。

断电后不清理身份、配置、签到或保护记录，不伪造健康心跳，不重新授予预约资格。成功回执必须同时核对重新上电、网络恢复、APK 启动、身份与房间保持、页面数据新鲜、灯控正确，以及要求关闭的 ADB 未自动重新打开。

交换机端口恢复只提供外部电源控制能力；若交换机管理也依赖同一失效路径，不能承诺完全带外可用。厂家预装或独立维护代理后续按实际缺口评估；首批不新增第二套看门狗 APK。

## 7. 建设阶段与任务分工

| 阶段 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|
| P0 单台交付基线 | 正式签名与型号基线、开机与 PoE 断电恢复、厂家安装／守护接口可行性 | 单台完整交付通过；2GB 新型号单独长稳；阻塞接口有明确人工替代 |
| P1 批量首装及前后台任务 | 安装工具、IP 清单、设备关联、房间映射、安装助手与后台任务、交付记录 | 少量试点后扩批；失败可定位、可重试，原有配置与业务隔离保持 |
| P2 长期维护底座 | 无 ADB APK 更新、页面版本与健康回执、交付后关闭 ADB、现场维护规则 | #16／#29 的真实升级、关闭、重启和维护恢复闭环通过 |
| P3 PoE 管理集成 | 交换机／端口登记、单端口供电操作和恢复核验 | 正确端口实际断电，其他端口不受影响，故障恢复供电验证通过 |
| 后续采购优化 | 厂家预装正式 APK、已验收固件和开机策略 | 联网即自动注册；只预装程序，不克隆注册身份、凭证或已绑定数据 |

手动 PoE 恢复和人工关闭 ADB 可先用于 P0／P1；不必等待交换机后台连接器完成才开始首批交付。P0／P1 的实际开发分别确定 Issue，#16 管 APK 与 H5 运维，#29 管 ADB 和维护优先级，#10 管网络与硬件长稳。各项分别标记实现及验收，不因总计划完成而关闭原 Issue。

## 8. 验证、发布与回退

- 后端：认证与角色、任务目标校验、幂等、地址复用／重绑定、超时与重试、设备及助手撤销、离线、版本不匹配；安装助手与交换机连接器使用 mock 隔离。按仓库规范执行 Ruff 和 pytest。
- 前端：已有台账与模板回归、新任务进度、失败提示、影响预览、只读权限、取消与刷新恢复；执行 npm ci、构建与 Playwright Chromium。
- Android：普通权限下的厂家服务连接、断连与安装失败、签名／版本拒绝、身份保留、生命周期与维护冲突；执行单元测试、lint、构建，安装升级另做实机验证。
- 实机：Wi-Fi／有线切换、IP 变化、首次授权、首装、升级、断网恢复、现场重开 ADB、关闭后冷启动、PoE 真断电、72 小时／7 天与跨昼夜。页面、应用、系统和电源恢复各自留证据。
- 发布分别明确服务器 SHA、APK 版本／摘要／签名、执行端版本、设备与交换机目标、维护窗口和回退流程；前后台上线、设备升级与电源操作分别处理。
- 不推送 main、不默认部署旧服务器、不迁入凭证或 SDK 私有二进制；原有 API、ROOM_DISPLAY_*、rooms:* 与 argus_room_* 保持兼容。新增原生源码目录前登记职责并补 ADR。
