# 会议室 Android 与 ESP32-P4 终端对照研发计划

> 2026-09-20 状态更新：用户已启动 Android 外壳实施，首轮使用到位的 RK3568 / Android 11 / 2GB / 1280×800 / WebView 106 门牌样机。三星仍可作为后续对照设备。实施见 [Android README](../android/README.md)；本文其他“仅规划”描述保留历史背景，ESP 未启动。

> 版本: 0.1 | 作者: RoomBeacon Team | 更新日期: 2026-09-16

## 1. 目标与当前状态

用户确定并行验证两种终端：现有三星 Galaxy Tab S8 平板运行 APK；购买 ESP32-P4 配 10.1 寸屏运行原生固件。以实际显示、恢复能力与连续运行结果决定后续选型。

用户明确本轮只做规划，不实际写代码。本文件为研发范围与验收计划，尚未交付 APK 或固件，未进行实物性能测试。三星已确认是 Galaxy Tab S8，Android/WebView 版本在实施时确认；用户所称 ESP32T4 暂按前文 ESP32-P4 理解，准确板型、芯片修订和屏幕型号待确认，微雪 PoE 套件仅作为候选。

## 2. 共用架构

- 继续使用独立门牌服务器的飞书集中采集与 Redis 缓存，两端均不直接请求飞书。
- 沿用 GET /api/meeting-rooms/display 和单会议室 Bearer 设备凭证，不在终端放 App Secret 或中控密码。
- Android 复用 V3 Vue 页面；ESP 使用 ESP-IDF 和 LVGL 重写显示层。中控仍在网页维护。
- 不替换 V1/V2/V3，不在硬件未知时固化 GPIO、显示驱动和以太网 PHY 参数。
- 原生客户端源码目录需先在 AGENTS.md 注册，并记录独立 ADR；新终端不改变现有服务器技术栈。

## 3. Android 首版范围

- 全屏 WebView 展示指定服务器的 V3；管理配置限定服务器与会议室，配置可持久化。
- 屏幕常亮、横屏/适配、限制网页外部跳转、隐藏维护入口加本机管理员密码。
- 网络恢复重试和 WebView 渲染进程异常恢复，保留最后成功日程并明确历史/未知状态。
- 分开实现普通试用与 Device Owner 专用设备锁定。普通全屏不能宣称可阻止系统退出。
- 开机恢复需按三星实际系统和设备管理方式验证；不承诺关机接电会自动启动，不擅自恢复出厂。
- 验证 WebView 对现有 cqw、容器查询和动态视口单位的支持，再决定兼容样式。
- 服务器可按当前环境使用 HTTP，HTTPS 校验不绕过；不硬编码服务器、凭证或密码。

## 4. ESP 首版范围

- 准确板型确认后从厂家 ESP-IDF 示例验证屏幕横屏、触控、以太网和 PoE 同时运行。
- 实现房间信息、三种状态、倒计时、后续两场、12 小时时间轴、日夜主题和签到二维码。
- 美术二维码优先由服务器提供可缓存的栅格图。品牌动画按板上实测内存和帧率适配，单列差异。
- 通过服务器时钟和单调时间维持倒计时；重启无可信时钟时显示待同步，不误报空闲。
- 后续补齐本地缓存、凭证配置、日志诊断、看门狗、OTA 校验与失败回退。
- 有线网络优先；灯带属于后续独立变量，不作为首轮对照的必要功能。

## 5. 对照方法

两端使用相同会议室和同一组固定测试日程，固定刷新周期和主题。实际业务验证与可重复的模拟边界测试分开。屏幕尺寸、分辨率、网络方式与亮度均记录，避免将设备尺寸差异归因于平台。

| 场景 | 记录 | 验收要点 |
|---|---|---|
| 状态切换 | 空闲、提前 15 分钟、使用中、会议结束的切换时刻 | 同一数据与时钟下两端一致 |
| 日程边界 | 跨日、取消、长中文名称、空组织者、没有后续会议 | 后续只显示两场，布局可读 |
| 二维码 | 明暗两主题、多手机实扫 | 解码为同一会议室签到入口，不伪造已签到 |
| 首次与热启动 | 至首个有效画面的耗时 | 区分联网加载和本地历史画面 |
| 断网与恢复 | 断网 1/10/30 分钟，恢复耗时 | 旧数据标历史；失效状态不显示可预约绿灯 |
| 服务端异常 | 超时、5xx、401/403 | 超时不阻塞 UI；撤销凭证不得继续当作正常 |
| 软件重启 | 配置保留、自动进入显示 | 无需重新手输会议室 |
| 断电恢复 | 多次断电、重上电、存储完整性 | 安卓关机接电与系统重启分开记录 |
| 连续运行 | 先 72 小时，再 7 天；内存趋势、崩溃、卡死、恢复次数 | 不以定时重启掩盖泄漏；看门狗恢复亦计故障 |
| 运维 | 更新、回退、重新绑定、密码维护 | 可恢复且不暴露管理员能力 |

功耗测量采用一致测量位置并注明供电损耗；三星电池供电不能与 ESP PoE 输入功耗直接比较。最终比较一次硬件成本、开发维护成本和实测故障，而不预设 ESP 更稳定。

## 6. 下一步

以下步骤仅在用户启动实施后执行，本轮不安装开发工具、不编写客户端、不部署或更改设备。

2. 确认 ESP 板型/芯片修订/屏幕并获取原理图、SDK 和实物。
3. 先取得 APK 实机基准，再使 ESP 达到核心功能一致，运行对照矩阵。
