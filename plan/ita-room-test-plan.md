## 2. 开始前的核对与当前规则

2026-10-10 文档基线为：BDC5ZS 正式 APK `0.7.1（11）`、WebView `106.0.5249.79`、H5 `3aaf5ee7dd91f0239d75675ee6dad8985f22687d`、配置回执 `3/3`、V7、页面 ready／灯控 ok。它是历史发布回执，不是本轮实时检查结果。

开始执行时保存以下基线；不满足时记录具体阻碍，先完成不依赖该条件的项目。

1. BDC5ZS 实物与台账身份一致，绑定唯一房间且仍为业务主控；保存准确应用/H5 SHA、APK/WebView、软硬件模板及期望/实际配置修订。
2. 原生页面健康、网页业务心跳、缓存新鲜度均有实时证据；不能只凭“在线”或 `3/3` 判断健康。
3. 本房规则是会前 5 分钟、开始后 5 分钟、补签到 0 秒；来源自动核验/释放开关与本次实例资格分别核对。保存当前策略，不重写旧保护或签到记录。
4. ITA `GET /healthz`、`GET /openapi.json`、带认证 `GET /v1/capabilities` 可用。只选 implemented 与 validated 的交集；本对话已只读验证接口及历史批次，但执行前仍要复核。
5. 只读检查本房拟用时段和已有预约。普通场次建议 30 分钟、开始至少预留 20 分钟、彼此不重叠。冲突时记录并重新编排，不删除既有预约或静默换房间。
6. 对开始后新增用例，先取得连续完整新鲜快照和稳定真实心跳。对故障用例，先预留恢复验证场次并记录样机原配置/联网方式。

当前规则决定预期：

- 正常预约开放时刻为 `开始－5 分钟`，截止为 `开始＋5 分钟`。截止后拒绝补签到；旧 B05 的一分钟补签到用例改为“零补签到边界”。
- 连续健康观察中可靠新增、且首次发现时已开始的预约，截止为 `min(首次可靠发现＋5 分钟, 结束时刻)`。首次采集、断网恢复、重启或旧记录重新出现不能据此获得新资格。
- 改期生成独立时间身份，新时间重新核验和签到；刷新、重采集、等待心跳、取消后重现均不得延长已有截止。
- 到点停止签到不等于立即释放。仅在核验、心跳、策略和发送前检查全部成立时，要求截止后 30 秒内完成单次释放及真实读回；未达标记录耗时和原因。
- 未签到自动释放由灯塔工作器执行。ITA 的“移除房间”是外部主动取消，用它代替灯塔释放会使该用例无效。

## 4. 第二组：重复、实例身份与来源

ITA 创建日/周/月重复时，会把每个原始发生点物化为真实例外后预约房间。因此必须区分“ITA 例外实例”与“飞书原生普通重复实例”：前者通过不能证明忙闲 `original_time=0` 的普通实例路径通过。

2026-10-11 复核：ITA 已通过API创建真实有限RRULE系列，逐次例外化是当前读回/预约验证实现选择，不是已经证明普通重复只能靠飞书界面创建。未物化的实例没有独立GET/attendees实体，现有程序因此PATCH后逐场订房；现有回执未证明向系列本体添加固定房间会被上游拒绝。

| T26 | P1 前后台与健康恢复 | 管理在线/配置回执曾掩盖页面异常；切桌面再回正式 APK | 后台暂停时灯灭、网页业务保活停止；返回后真实页面探测和新鲜数据恢复，旧保护不静默重置，页面/灯控健康与实物一致 |
| T27 | P1 长标题、三栏、后续与动图 | 旧 1280×720 双卡片溢出17px、上滑裁顶、动图裁剪/遮挡 | 使用本批长标题和连续日程，按实时 viewport 检查整页、底边、时间轴、按钮；无溢出遮挡，品牌动图正常，装饰不截获触摸 |
| T28 | P2 背景、保密、昼夜/语言 | JPEG 曾转PNG膨胀导致失败；保密模板实机效果待验收 | 先隔离预览/独立草稿核验原格式字节、cover裁切/contain留白、名称隐藏及日夜/语言。仅在影响范围确为本机时做实机部署，结束恢复准确原版本 |
| T29 | P2 单机冷启动与网络切换 | 旧启动项指 debug 包；PoE/有线恢复尚待实机 | 现场只对本机真断电，或单机Wi‑Fi/有线切换；正式APK自动启动、原身份/房间/配置保留、HTTPS/页面/灯恢复。不得重启共享交换机；无端口映射记待配合 |

## 6. 第四组：API 边界、隔离故障与长期观察

下列故障注入不连接生产 Redis，不向飞书发送模拟故障下的真实业务写入，不改变共享服务。实机仅观察自然发生的上游错误，并记录本房受影响实例。

| 编号 | 优先级／场景 | 依据与执行方法 | 通过标准 |
|---|---|---|---|
| T30 | P0 来源失败/权限/限流 | 隔离复现错日历404/193001、缺权限、身份歧义、429和超时 | 原因可定位、退避有界，不授予未知资格，不拿错误来源兜底，保护旧会议 |
| T31 | P0 502/503/504与缓存过期 | 历史504重试耗尽导致测试中断；隔离短暂及持续失败、过期、查询范围缺失 | 读重试有限、不延长旧缓存，不误报空闲，不释放；恢复首份仅建基线，不补删保护场 |
| T32 | P0 释放失败/响应丢失/读回失败 | 隔离明确失败、写结果未知、写成功但读回失败、较慢旧采集覆盖新快照 | 无假成功，未知写入不重发，缓存原子/新旧时序正确；保留可读回执、残留及错误 |
| T33 | P0 并发签到/撤权/暂停 | 隔离临发送前签到、策略变更、房间资格撤销、重复工作器 | 最后检查生效，签到与释放无双成功、外部发送最多一次；恢复不补授旧记录。生产不切全局暂停 |
| T34 | P0 API认证/幂等/版本 | 无Token401；本轮资产同键同请求重放、同键变正文409、缺If-Match428、过期412、未知字段/非法时区422 | 重放不多建/多删，所有失败不误写；任务202/GET200不能当业务成功；撤销真实Token/越权身份仅隔离验证 |

| T36 | P1 策略/暂停持久化 | 历史策略7天TTL到期使签到资格丢失；只读检查本房策略，隔离推进时间/记录丢失 | 长期策略按设计持久，短期实例/心跳仍过期；记录丢失不误授旧会议；真实72小时不代替7天TTL边界验证 |
| T37 | P0 连续72小时 | 最新门槛已从旧B12的24–48小时升级；在P0功能通过后持续运行 | 覆盖有效预约、连续场次、跨日、恢复及多组织者；符合条件场次保留/释放100%正确、误释放/重复发送0，失败全部归因，无未解决核心缺陷 |

|---|---|---|---|

| 2 | T05–T09、T11、T14、T23–T27 | 1天；每个故障有独立场次和恢复场 | 晚预约、变更、新会话与失联保护；无上一个故障未恢复就启动下一项 |

## 8. ITA 调用、灯塔观察与证据

每轮新建独立 run，每个 run 最多20条登记日程；标题使用 `RBTEST-日期-用例-短随机码`，记录完整请求、幂等键和返回的服务编号。普通改期/取消/重订/删除先 GET event，实例操作先 GET occurrence，cleanup 先 GET run，将带引号 ETag 原样传给 `If-Match`。

每次写入取得202后，每10秒 GET job，直到 `terminal=true`；还要核对 status、逐步骤 error/receipt、残留和业务读回。`succeeded` 仅证明 ITA 的飞书动作；当前 `observation_available=false`、任务 `not_requested`，必须由灯塔侧独立完成同步/实机判定。

ITA 的 `event_ref/occurrence_ref` 不是飞书 UID。先按本轮唯一标题和精确起止时间从本房管理员快照定位，再记录灯塔 `uid/original_time/起止时间`；找到多个或找不到时停止该项写操作并对账。签到只通过真实 BDC5ZS 操作；只读预览、后台确认和伪造心跳不能代替实机。

灯塔观察遵守自然采集，不改缓存、不强制全房刷新。只读轮询建议15秒，普通同步观察预算为“两轮实际采集周期＋60秒”（若周期300秒则660秒）；这是测试观察器预算，不能延长业务截止或靠超时重发写请求。

- 创建/重订：写后新鲜快照中目标身份与时间正确出现。
- 改期：旧时间消失、新时间出现，新身份状态独立；不能只比较标题。
- 移除/删除/自动释放：写后新鲜且覆盖相应时段的快照中目标缺失，并有飞书回读，不能用旧空快照证明成功。
- 重复：记录所有本轮实例的原始发生点与前后差异；未来窗口之外只做飞书核验，记“实机窗口之外”，既不判失败，也不勾实机通过。
- 正常未签到释放：计时以服务器持久截止为准，核对灯塔发送次数、实际响应/读回耗时及BDC5ZS更新；故障保护场的“应保留”也是必须验证的预期。

每项报告至少包含：

| 字段 | 内容 |
|---|---|
| 标识 | 用例/子项、执行环境、run/job/event/occurrence服务编号、唯一room_id、BDC5ZS设备标识 |
| 基线 | 准确应用/H5 SHA、APK/WebView、模板/策略修订、源日历脱敏摘要 |
| 时间 | 创建/修改回执、原始开始、新开始、结束、首次可靠发现、服务器截止、发送与读回时刻 |
| 三侧证据 | ITA作业与飞书业务读回；本房缓存及usage/审计；BDC5ZS真实截图/视频和现场灯色 |
| 新鲜度 | synced_at、valid_until、server_time；query_start/query_end从允许的诊断证据取得，公共响应缺字段不能自造 |
| 结论 | 通过/失败/待配合/范围条件未满足/实机窗口之外/仅隔离通过，以及具体原因 |
| 清理 | 最新ETag、cleanup job、残留、人工系列清理责任、样机联网/应用/配置恢复结果 |

脱敏总结可入库；凭证、真实会话、私有源日历标识和原始回执存本地忽略目录。旧9月验证、ITA历史任务和本轮新结果分开编号。候选软件变化后重验受影响用例；不混用不同SHA统计成功率。

## 9. 中止、清理与完成标准

遇到目标不一致、真实其他房间出现在请求、身份匹配歧义、非本批次资产、错误释放、重复发送或 `unknown` 结果，停止受影响轮次，保存原请求/标识并只读对账。不能换幂等键盲目重发、清保护记录、重建预约或改全局开关补造成功。

每轮结束 GET 最新 run，再按版本请求本 run cleanup。已知 partial 按 residual_targets 核对后处理；unknown 先由 ITA 维护者按原 job_id 恢复只读对账，结果明确后才清理。cleanup 只处理服务登记的本轮资产，不清其他批次、本人其他日程或本房原有预约。人工原生系列由登记的创建者按约定单独清理。

最后确认本轮目标均已取消/移除、残留为空，本房原有日程未改，BDC5ZS原身份/房间/应用/联网和原配置恢复且有新鲜真实回执。软件仅按原版本恢复，不卸载、不清数据、不整库回退。

完成门槛：本机/本房适用P0全部有明确通过证据，零误释放、零重复外部写入、零跨场签到、零越界；正常条件截止后30秒内释放和读回，保护条件按预期保留；72小时有有效场次及全部错误归因。多组织者或原生普通重复尚待配合时，只报告已覆盖单身份/例外范围，不能宣布全来源、全重复或完整正式验收通过。
